# D86

## Decision

`loopherd view` paints its roles from one of three palettes: `purple-orange`
(the install splash's, and the default), `phosphor` (junderdo.dev's Tailwind
green-400, amber-300 and stone) and `catppuccin` (Mocha). Red, green and
yellow status colors stay the same in every palette, and `NO_COLOR` and the
256-color fallback apply to each.

- **Switching.** `t` moves to the next palette and redraws at once; the
  footer lists `t theme`.
- **Persisting.** Each switch writes `view.theme` to `config.toml`
  (`purple-orange`, `phosphor` or `catppuccin`) at once from the input
  loop, keeping the file's comments; a failed write shows
  `save theme: <error>` in the notes and the view keeps the new palette.
- **Starting.** `view` starts in `view.theme`. An unknown name, or a
  `config.toml` that can't be read, starts it in `purple-orange` with the
  reason in its notes line until the first key, so a popup view that closes
  on exit still shows it.
- **Config command.** `loopherd config get|set|unset view.theme` reads and
  edits it; `set` refuses a name that isn't one of the three. `config get`
  now prints every key as text.

## Why

Asked by the human on LH-285 (2026-11-19). herdr's `catppuccin` theme is the
Mocha flavor (its light variant is the separate `catppuccin-latte`), so the
Catppuccin palette uses Mocha's values. `config.toml` can't fail to load
over an unknown theme name: `[view] theme` is kept as text and checked
only by `view`, so a stale name costs only the palette (a misspelled key
or a non-string value in `[view]` still fails the file, like any other
table). The save runs in the input loop rather than the reader thread:
queued behind a hung herdr read, it would be lost when `q` exits.

Limit: a `loopherd` built before this refuses a `config.toml` with a
`[view]` table (unknown field), so after `t` an older binary still on
PATH, such as the Stop hook's, can't read the file until reinstalled.
