# D86

## Decision

`loopherd view` paints its roles from one of three palettes: `purple-orange`
(the install splash's, and the default), `phosphor` (junderdo.dev's Tailwind
green-400, amber-300 and stone) and `catppuccin` (Mocha). Red, green and
yellow status colors stay the same in every palette, and `NO_COLOR` and the
256-color fallback apply to each.

- **Switching.** `t` moves to the next palette and redraws at once; the
  footer lists `t theme`.
- **Persisting.** Each switch asks the reader thread to write `view.theme`
  to `config.toml` (`purple-orange`, `phosphor` or `catppuccin`), keeping
  the file's comments; a failed write shows `save theme: <error>` in the
  notes and the view keeps the new palette.
- **Starting.** `view` starts in `view.theme`. An unknown name, or a
  `config.toml` that can't be read, prints a warning on stderr (shown once
  the view exits) and starts in `purple-orange`.
- **Config command.** `loopherd config get|set|unset view.theme` reads and
  edits it; `set` refuses a name that isn't one of the three. `config get`
  now prints every key as text.

## Why

Asked by the human on LH-285 (2026-11-19). herdr's `catppuccin` theme is the
Mocha flavor (its light variant is the separate `catppuccin-latte`), so the
Catppuccin palette uses Mocha's values. `config.toml` can't fail to load
over a theme name: `[view] theme` is kept as text and checked only by
`view`, so a stale name costs only the palette. Writing from the reader
thread keeps the input loop free of file I/O, like herdr and ledger reads.
