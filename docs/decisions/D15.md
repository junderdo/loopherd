# D15

## Decision

Slice 6 builds the **shepherd's** tools first, shaped so a lead member (a
loopherd-run agent dispatching to workers) can use them later; no lead member
(built later as D17) and no new dispatch commands yet (`feed`, `add`, `herdr
agent prompt` suffice). **Mailbox:** a member runs `loopherd report [--kind
done|question|note] [--as <name>] <text>` (default `note`); it's identified by
`HERDR_PANE_ID` against non-retired ledger entries, else `--as`, else an
error. Reports append as JSON lines to
`$XDG_STATE_HOME/loopherd/reports/<name>.jsonl` and survive retire. `loopherd
reports [<name>…] [--herd <h>] [--all]` prints those newer than one reader
cursor and advances it; `--all` prints history without moving it. This is the
one loopherd command members run against the real state dir. **Watch:**
`loopherd watch [<herd>…] [--timeout <secs>]` polls `agent list` every 2s
through the status core and returns on an unread report (including at start),
a member going `blocked` while watched (one already `blocked` at start doesn't
wake it, so re-arming after a wake doesn't re-wake on a dialog still waiting
for the human; the shepherd runs `loopherd status` on starting a session to
catch those), or a member going `working` → `done`/`idle`/`gone` (its pane
disappeared; stops moved to the mailbox in D16); it prints one plain line per
event, `question` first, advances the cursor, and exits 0, or exits 2 at the
timeout. It watches every non-retired member, narrowed by herd, never strays.
loopherd never prompts the shepherd itself (D10). LH-44 later moves `view` and
`watch` to events. Built as LH-58 (mailbox) then LH-59 (watch).

## Why

The shepherd learned of members stopping only by a per-member `herdr agent
wait` that dies with its session, and read their screens, lossy and gone once
a pane closes. A report persists; a status change is only a nudge. Grilled
with the human 2026-11-01.
