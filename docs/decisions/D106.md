# D106

## Decision

Amends D97, D98 and D102 (LH-307). A lead's sandbox writes, in the state
dir, only its own handoff directory and its own broker's `requests/`.

- **Handoffs, one directory per agent.** Every agent, the shepherd
  included, writes `handoffs/<name>/handoff.md`; once read it moves to
  `prev.md` beside it.
  - The Stop hook's ask, `restart`, `restart --self`, the shepherd's
    SessionStart resume and `herd remove` all use the new place.
  - Readers fall back to the flat `handoffs/<name>.md` an older release
    wrote, and move it into the new directory's `prev.md` once used. New
    handoffs are written only to the new place. A later release drops
    the fallback.
  - `shepherd` stays a reserved name.
- **A lead's report goes through its broker**, as a `report` request the
  broker writes to the lead's own mailbox; a question also labels its
  pane there, replacing the separate label request. With no broker
  running, the report fails like the lead's other routed commands.
- **The lead's `allowWrite` in the state dir** is `handoffs/<lead>/` and
  `broker/<lead>/requests/`, nothing else. `reports/` leaves it, and with
  it the shepherd's watch-file denies, which only guarded files inside an
  allowed `reports/`.
- **The file tools** are denied `reports/` whole, and, as D102 does for
  `broker/`:
  - on Linux, `Edit(//<state>/handoffs/*)`, a glob the Linux sandbox
    skips, so Bash keeps its own directory while the file tools are
    refused all of `handoffs/`, the lead's own directory and directories
    made later included;
  - on every platform, a literal deny on each entry of `handoffs/` but
    the lead's own, as they stand when its settings are written.
  - A lead writes its handoff with Bash.
- **`lead`, `revive` and `restart` make `handoffs/<lead>/`**, the
  shepherd's and every herd's lead's handoff directory before the lead's
  Claude starts or is cleared, so a literal deny names them. No literal
  deny covers the lead's own directory.

## Why

- **Separation by directory, not by name.** A deny on one file inside an
  allowed directory doesn't outlast a rename from outside the sandbox
  (D97). With each agent's handoff in a directory of its own, the
  sandbox allows just the lead's.
- **The shepherd follows its handoff unsandboxed.** Before this, a lead
  could write `handoffs/shepherd.md`, which the shepherd's resume reads
  and acts on. The flat fallback keeps that path readable for an
  upgrade, so the file tools' glob refuses planting a new flat file too.
- **`reports/` needed nothing from inside the sandbox any more.** The
  lead's watch runs outside it (D104), and its report now runs in its
  broker. D98 kept the report in the lead because a single-threaded
  broker could leave it waiting behind a long feed; the broker now
  answers quick requests while a feed runs (LH-311).
- **The glob costs the lead's file tools its own handoff.** No glob can
  mean "every name but this one" (D102), and a literal deny alone misses
  directories made after the lead's settings were written, such as a
  later worker's. A heredoc in Bash writes the handoff as well.
- **The live sandboxed-lead test checks it.** From inside a real lead's
  sandbox, Bash is refused its own mailbox, another agent's mailbox, the
  shepherd's handoff in both layouts and another agent's handoff
  directory, and writes its own handoff; the Write tool is refused a
  flat shepherd handoff, a mailbox and a handoff directory made after
  the lead started; its report and `restart --self` go through its
  broker. The live watch test shows the bare watch writing its lock in
  `reports/` from outside the sandbox.

## Still open

- **macOS** applies globs, so there the lead's file tools get only the
  literal denies and may write a handoff directory made after the lead's
  settings were written, until its Claude starts again. Its Bash still
  can't. Not run on macOS.
- A lead running `loopherd watch` in a form that keeps it inside the
  sandbox (D104) now fails at once on `reports/`, rather than blocking
  `git config` writes.
- Lock files a lead can still `flock` read-only are LH-313's.
