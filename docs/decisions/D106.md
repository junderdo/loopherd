# D106

## Decision

`loopherd broker-restart <lead>` replaces a lead's broker (D98) with one on
the current binary. Amends D98.

- **Stop by a file, not a signal.** Each broker writes its pid to
  `<config dir>/broker/<lead>.pid`, removed when it exits. The restart
  flocks `<lead>.restart` for as long as it runs, and writes the old
  broker's pid to `<lead>.stop`. While that lock is held and the stop names
  its own pid, a broker starts no request, in any lane, and exits once those
  in flight are answered; the rest stay in `requests/`. The new broker
  ignores a stop naming another pid. A restart that was killed lets go of
  its lock, so its leftover stop is obeyed by nothing, whatever pids are
  later reused. A lock, not a pid, because a sandboxed lead's loopherd runs
  in its own pid namespace and can't see the restart's process. A second
  restart of the same lead is refused while one holds the lock.
- **Bounded, never forced.** The restart waits as long as a lead waits on a
  feed (4 hours). A broker still busy then is left running: the stop file
  is removed, and if the broker still holds its lock half a second later
  (a broker that stopped at the bound still joins its lanes) the command
  fails naming its pid. No signal is ever sent.
- **Clients ride the gap.** While a restart holds its lock and its stop
  exists, a lead's request waits out a missing broker instead of failing,
  so a request written while the old broker stops is served by the new one.
- **The shepherd's or the human's.** Refused from a lead's pane or sandbox,
  inside a broker (whose `after_merge` would wait on itself), and no broker
  op carries it.

## Why

After every merge that changed the broker, the fix was `kill <pid>` then
`revive --name <lead>`, which killed a request in flight and which Claude
Code's auto mode blocked for the shepherd. A signal would have to be
delivered to a real process, which in-process tests of `serve` can't do;
a file in the config dir is testable, and the lead can read it but not
write it. Brokers started before this have no pid file, so the restart
refuses them, naming how to stop them by hand once.
