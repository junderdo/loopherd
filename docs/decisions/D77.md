# D77

## Decision

A moved member's `env_pane_id` belongs to the process that inherited it,
the member's recorded Claude, and is dropped once that process is known to
have been replaced:

- `revive` drops it whenever it starts the member again, in its own pane or
  a new one, since the new Claude takes the pane's current id.
- `revive` drops it from a member it finds alive whose recorded process is
  gone: herdr resumed it in a restored pane, whose shell carries the current
  id. A member whose recorded process still runs keeps it, as does one with
  no recorded process, which can't be told apart.
- The Stop and SessionStart hooks drop it when they claim a new process for
  the member from its current `pane_id`. Until a herdr restart, every
  process in a moved pane inherits the old id, so a claim from the current
  one means the old process is gone. A claim from `env_pane_id` keeps it.

This amends D74: its limit on a reused workspace id handing a moved
member's old id to a new pane is gone, and its other limits stand.

Limits:

- A moved member that neither herdr nor `revive` starts again after a
  restart keeps `env_pane_id`, so an agent in a new pane with that id still
  resolves to it until the member is revived or retired. A stale `pane_id`
  does the same.

LH-271 settled it.

## Why

After a herdr restart no pane process survives, and every restored shell
carries its pane's current id, so the old id can only reach a process in
another pane. Clearing on a replaced process rather than on every revive
keeps the id for a member whose own process still runs, which still needs
it for its reports and hooks.
