# D159

## Decision

Amends D149. `loopherd gate` runs each `[lead] gate` command without
`LOOPHERD_BROKER_OF` (LH-561). A gate checks another checkout; a
`loopherd` it starts, such as one a test spawns, is not a request the
broker serves, so it must not refuse or wait as if it were.

- **Removed:** `LOOPHERD_BROKER_OF` only. `LOOPHERD_BROKER_LOCK_FD` and
  `LOOPHERD_BROKER_STARTED_FROM` are already removed when the broker
  starts, so nothing it runs sees them.
- **Kept:** what the broker's start set from the lead's launch record and
  herd: `PATH`, and in a `credentials` herd its credentials and
  `GIT_SSH_COMMAND`. A gate's commands build and fetch as the lead's
  sandbox would.
- **After-merge commands keep it.** A herd's `after_merge` may run
  `scripts/install`, whose `loopherd doctor` reads `LOOPHERD_BROKER_OF` to
  see that the broker running it moves onto the new install.
- **Tests.** Every test helper that spawns `loopherd` removes
  `LOOPHERD_BROKER_OF`, so `cargo test` behaves the same inside a broker.

## Why

The first lead self-gates of this repo hung: the gate's `cargo test`
inherited the broker's identity, `tests/broker_restart.rs` spawned
`loopherd broker-restart`, which refused as a broker's own request, and
the test waited until the gate's timeout reported a failure that wasn't
the PR's.
