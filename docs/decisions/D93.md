# D93

## Decision

`loopherd view --beside-shepherd` (D87) changes three ways:

- **No stacking.** Before splitting, it looks in the target pane's tab for
  a pane labelled `loopherd view`, the view pane's manifest title, and
  focuses it with `plugin pane focus`. herdr refuses that for any pane that
  isn't a plugin's, and then a new view opens as before. Run from a view
  pane, the action focuses that view.
- **Visible when off-screen.** When the focused workspace's active tab
  isn't the target's, the split opens with `--focus`, which switches the
  human to that tab and workspace. Otherwise focus stays where it was. An
  unreadable workspace list counts as on-screen.
- **Share at most half.** A split opens at half and only the target's right
  divider is resized, so a `Placement::RightOf` share over 0.5 is refused
  before anything opens. Growing the new pane would mean moving the
  target's left edge, an outer divider when it already sits inside a split.

## Why

LH-290, from PR 262's review. Repeating the action stacked 40% splits. A
shepherd in another tab got its view out of sight, reported only in the
plugin log. Only the 0.4 share is used, so refusing wider shares was cheaper
than resizing the new pane's left edge.
