# D75

## Decision

`loopherd retire <name>`, with or without `--close`, refuses and changes
nothing when the entry isn't retired yet, herdr still shows its agent (any
status), and its mailbox has no `done`, `question` or `handoff` report since
its last `start`. `--force` retires it anyway. A member herdr no longer shows
retires without a report, and an already-retired entry takes `--close` as
before. Feed's retire after a passing `done` check and `herd remove` don't
run the check. A revive's resumed start doesn't reset the check, since the
member resumes the same conversation. A herdr that can't be reached has no
live panes, so retire goes ahead; one that doesn't answer within 5s, or
whose agent list loopherd can't parse, makes it refuse and name `--force`.

A lead's PreToolUse hook denies `loopherd retire --force` in its pane,
whatever its switches, as it denies `restart --force` (D20).

## Why

A retire meant for an earlier run of a name found the released and re-fed
member instead, retired it and closed its tab mid-task. Both conditions are
required so a lead can still clean up a dead worker without the
hook-denied `--force`.
