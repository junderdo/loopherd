# D181

## Decision

A local tracker's batch grill posts its batch as a commit on the member's own
branch, `docs/{id}-{slug}`, pushed with no PR, so nothing reaches the default
branch before the human answers (LH-605). Amends D132's "commits and pushes
nothing until the human answers" and D179's "local is deferred". From a batch
grill accepted on LH-605.

- **The post.** The member appends the batch under the issue file's
  `## Comments`, sets that file's `Status:` to `needs-info grilling
  grill:batch`, commits, and pushes the branch with no PR. That commit is the
  local tracker's comment, as a card comment is on Trello or GitHub; main's
  copy of the file is untouched.
- **D132, narrowed.** "Nothing before the answer" means nothing reaches the
  default branch and nothing is filed or marked ready. A commit on the
  member's own branch is allowed, since it is the only way a local task can
  take a comment.
- **`done`** passes when `origin/main:{path}`'s Status is resolved, closed or
  done, or when `git fetch -q origin {branch}` succeeds and
  `origin/{branch}:{path}`'s Status holds `needs-info`. A missing branch or
  file is not done. Feed reaps the member either way.
- **The source reads main only.** Main's Status still says `grilling
  grill:batch` while the batch waits; feed skips the retired, unreleased name
  (D51), so the task isn't refed before release.
- **The answer.** The human answers wherever they read the batch: the
  shepherd's pane, or a lead's question. That shepherd or lead, not the human,
  appends the reply under the batch in the issue file on the member's branch,
  commits and pushes it, then runs `loopherd release --keep-branch <member>`.
  The next member continues from origin's branch, reads the comments after
  the latest round as the answer and sets `Status:` back to `claimed`. A
  plain release refuses the branch, which holds commits not on the base, so
  the batch can't be dropped by accident.
- **The outcome** sets `Status: resolved` and opens the PR from the same
  branch, so the batch, its answer and the decision reach main together.
- **Routing.** A `Status:` line holding both `grilling` and `grill:batch`
  routes to `grill-batch` as type `docs` with the `grilling` skill, without
  `ready-for-agent`, ahead of any wayfinding word; `grilling` without
  `grill:batch` is left out, ready or not. The `Type:` line is not read. This
  is D179's GitHub rule.
- **Names** are `{herd}-grill-batch-{id}`; the source cuts its room 12 more
  for those issues, as it cuts 9 for research, and skips with a stderr line
  when the herd name leaves none.
- **The prompt** is D179's `grill-batch.md` with local fills for the post,
  the wait (nothing further: the commit is the wait) and the release text.
- **Slices.** Init offers it to a local herd first; `herd upgrade`'s
  grill-batch migration offers it after, blocked by the first.

## Why

A local issue lives on the default branch, so D179's first cut pushed the
batch to main before the answer, which fails on a protected main and leaves
the member unreaped. The member's own branch is where the local issue
template's needs-info stop already commits, never touches the default branch,
and `release --keep-branch` already carries it to the next member.

- **Branch over a file outside the repo:** a file outside is lost to
  release's worktree cleanup and invisible from another machine.
- **Branch over allowing the push to main:** a protected main refuses it.
- **The shepherd or lead appends the reply, not the human:** the human
  reads the batch where the herd talks to them, so whoever relays the
  question records the answer and releases in one step.
