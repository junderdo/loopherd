# D42

## Decision

`loopherd herd remove <herd>` deletes a finished herd completely: its herd
file, its pause file, its `[lead]` `prompt_file`, and each member's ledger
entry, mailbox (`reports/<name>.jsonl`) and handoffs (`handoffs/<name>.md`
and `<name>.prev.md`). The herd then leaves `herds`, `status --all` and
`stats`.

- It refuses, changing nothing, while any of the herd's ledger entries,
  lead included, is not retired, or is retired but herdr still shows its
  agent or tab open, and prints `loopherd retire --close <name>` for each
  with why. Retired is not enough: `retire` without `--close`, a tab close
  that failed after retiring, or a lead retiring itself all leave a
  running pane behind, and removing its entry would leave nothing
  `retire --close` could clean it up from. The tab is found as
  `retire --close` finds it (by agent name, else the recorded pane in its
  workspace and cwd); a recorded pane now held by another agent or entry
  doesn't count. When herdr can't be reached it refuses too. A herd with
  no ledger entries never asks herdr. There is no `--force` that retires
  for you.
- It never touches worktrees, branches or herdr tabs: that stays
  `retire --close`'s job.
- The lead's `prompt_file` goes only when it resolves inside the herds
  dir and no other herd file names it, as its lead's or any template's
  `prompt_file`. A herd file that can't be parsed counts as naming it.
  A kept prompt gets a `kept <path>: <why>` line.
- Ledger entries go through a new `Ledger::remove_herd`, which re-reads the
  ledger under its lock, re-checks that every entry is retired, and deletes
  the mailboxes and handoffs of exactly the names it removes while holding
  the lock, saving nothing if a delete fails. A concurrent write survives,
  and a name reused by another herd meanwhile keeps its files.
- It refuses, changing nothing, when `reports/` or `handoffs/` is a
  symlink, so it never deletes outside the state dir. A file it can't stat
  is an error, not read as absent. A `[lead]` `prompt_file` that isn't a
  regular file is kept.
- Every line for what it already removed is printed even when it then
  fails.
- A herd known only by ledger entries (no herd file) or only by its file
  (no entries) is removed too; one with neither is an error.
- `--dry-run` prints every path and ledger entry it would remove.
  `--keep-history` keeps the ledger entries and mailboxes, so `stats`
  still counts them, and removes the rest.
- Order: members' files, then ledger entries, then the pause, prompt and
  herd file last, so a run that fails partway can be rerun: the herd is
  still known by its file or its entries.
- The PreToolUse hook denies `loopherd herd remove` in a lead's pane
  whatever its switches, as for `herd set` (D29).

## Why

Removing the old `zagops-prs` herd took a hand `jq` edit of `ledger.json`
under `flock`, which is easy to get wrong while other writers run. Refusing
live members keeps removal from stranding a running agent with no ledger
entry. Leaving worktrees and tabs to `retire --close` keeps one command
responsible for cleaning up a member's checkout, with its clean-and-merged
checks. Herd files are the human's, so a lead may not delete its own.
