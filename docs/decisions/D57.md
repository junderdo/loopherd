# D57

## Decision

With `[notify] pane_label = true` (default false, and only while
`enabled = true`), loopherd labels in herdr's sidebar the pane of whoever must
relay or answer what waits on the human. The label goes through
`herdr pane report-metadata <pane> --source loopherd --agent claude
--display-agent <label>`, not herdr's `blocked` state.

- **Set.** The shepherd's watch labels its own pane when it prints a
  `question` line (`<member> asks: <first line>`, redacted as `[notify]`
  redacts the toast) or a member's `blocked` line (`<member> is blocked`),
  using the first such event, whatever `kinds` says. A pane that holds a
  member never labels from a watch, even one read as the shepherd's. A lead's `loopherd report --kind question`
  from its own pane labels that pane. A lead's watch never labels: the lead
  relays a worker's question as its own report, which labels it, and a
  question the lead settles itself would otherwise leave a stale label.
- **Clear.** A `UserPromptSubmit` hook (`loopherd prompt-hook`) clears the
  label in its pane, since the human's next message there is the answer, and
  so does a `SessionStart` from `startup`, `resume` or `clear`, so a crashed
  or cleared session isn't left labelled; `compact` and `fork` keep it. A
  prompt made only of whole `<task-notification>` blocks keeps it: Claude
  submits a finished background task as a prompt, and the shepherd's watch
  is one. Any other text in the prompt, before or after a block, clears it,
  as does input the hook can't read, so a format change errs toward no
  label.
- A mark per pane, `.pane-label-<pane>` in the mailboxes directory, says
  which panes loopherd labelled. A hook in an unmarked pane makes no herdr
  call, so every other prompt stays cheap. A set and a clear each hold a
  per-pane flock (`.pane-label-<pane>.lock`) across the mark change and the
  herdr call, so they can't interleave into a label with no mark. The mark
  is written before the label; a clear removes it before calling herdr and
  writes it back if herdr fails, so a failure costs one extra clear, never a
  label that stays.
- The mark is keyed on the pane ID alone. Two herdr servers sharing one
  state dir can clear each other's marks for the same pane ID, leaving a
  label until that pane's next one is cleared.
- Any other prompt Claude submits on its own, such as a scheduled one,
  clears the label as a typed one does.
- No `--ttl-ms`: a question can wait longer than herdr's 24 hour cap, and the
  hooks clear the label.
- `watch` doesn't require the prompt hook installed. Without it a label
  stays until the pane's next session starts.

LH-206 built it.

## Why

herdr 0.9.5 ignores lifecycle state from any source but the pane's owner, so
loopherd can't show the `blocked` icon on a Claude pane
([research/herdr.md](../research/herdr.md#labelling-a-claude-pane-095-lh-206);
herdr#2824, discussion herdr#3625). Display metadata is accepted, and
`--display-agent` is the one field herdr's default sidebar shows, in place
of the agent's name. `--title` shows nowhere in the default sidebar, and
`--state-label` and tokens only in a layout the human writes themselves.

The label never changes `agent_status`, so no watch can read it as a
`blocked` dialog, and a lead with `blocked_dialogs` on never tries to
answer it.
