# D140

## Decision

The paginated GitHub reads in `merge-guard` and doctor (the deploy-key and
ruleset lists) run `gh api --paginate` without `--slurp` (LH-396), and
parse the single array gh merges a REST list's pages into.

- **Minimum gh.** That merging shipped in gh 2.31.0 (cli/cli#7190);
  `--slurp` needs gh 2.48.0. An older gh prints one array per page, and a
  list over one page then fails to parse rather than reading short.
- **Errors name the endpoint.** A failed or timed-out `gh api` call in
  doctor reads `gh api <endpoint>: …`, not `gh api --paginate: …`.

## Why

`--slurp` raised the gh loopherd needs from 2.31.0 to 2.48.0 for no gain:
both give the whole list, and on gh 2.31–2.47 `--slurp` fails outright
with `unknown flag: --slurp`. Dropping it keeps the lower floor without a
version check of our own.
