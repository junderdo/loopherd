# D67

## Decision

The herdr plugin declares a `[[link_handlers]]` entry for
`^https://github\.com/[^/]+/[^/]+/pull/[0-9]+` that runs the `pr-member`
action, `sh loopherd.sh pr`. `loopherd pr` reads
`HERDR_PLUGIN_CLICKED_URL`, cuts it to the PR's own URL (dropping
`/files`, a query or a fragment) and looks for its owner:

1. The member on the PR's head branch in the PR's head repo, both from one
   `gh pr view <url> --json
   headRefName,headRepository,headRepositoryOwner`. The branch is its
   recorded `branch`, or for a detached spawn its worktree's branch now.
   The repo is its worktree's `origin`, or when that can't be read (a
   removed worktree) the `origin` of the repo it was spawned from, read as
   `owner/name` on github.com (host `github.com`, `www.github.com` or
   `ssh.github.com`, any case, as `loopherd init` accepts) and compared to
   the head repo ignoring case. A member whose origin can't be read, or
   isn't on github.com, never matches, and a PR whose head repo is gone (a
   deleted fork) has no head to match. An open member wins over a retired
   one, since a branch can be handed to a successor; the first open match
   by name wins. If only retired members are on it, the PR has no owner.
   The click waits on `gh` for at most 5 seconds, not the remote timeout,
   so a dead network costs a click that long before the fallback.
2. When GitHub can't be asked, has no such PR, or names a branch none of
   ours is on: the open worker (leads skipped) whose current run (entries
   since its ledger `created`) has a report naming the URL, ignoring case
   and not running on into a longer number. The earliest such report wins,
   since the member that opened the PR reports it before anyone reviewing
   it does. A mailbox that can't be read is skipped with a warning.

With an owner it opens the plugin's `pr-member` pane, `placement =
"popup"`, passing `LOOPHERD_PR_MEMBER` and the cut `LOOPHERD_PR_URL`
through `herdr plugin pane open --env`. That pane runs `loopherd pr
--popup`, which prints the member, herd, live status, template, review
round (its `done` reports this run, as `stats` counts rounds) and last
five reports, each cut to the popup's width in terminal columns so the
card never scrolls, then waits in raw mode for q or Escape. herdr closes a
popup when its command exits, so a card that can't be built prints its
error, cut the same way, and waits too. It takes raw mode and waits only
when stdin is a terminal; otherwise crossterm would take the caller's
`/dev/tty`.

Without an owner, or when the ledger can't be read, or when herdr refuses
the popup (another modal open), it opens the clicked link, anchor and all,
with `xdg-open`, or `open` on macOS, started with null stdio and not
waited on. Unlike herdr's own link opening, which runs on the client, this
runs on the server, so it reaches the browser of the machine and display
the server runs on.

The card's live test (Ctrl-click a member's PR link in `scripts/herdr-dev`
with the plugin linked) is split. Linking the plugin into the dev server
registers it in the human's live herdr (D62), and herdr can't fake a
Ctrl-click, so the click half is tests against the herdr fake and the
built binary with stubbed `gh`, `herdr` and `xdg-open`. The popup half is
a live test on a herdr server of its own in a throwaway home (D65's
`IsolatedServer`): it opens the `pr-member` pane with the member's env and
checks `loopherd pr --popup` runs, waits for a key, and ends on
`popup.close`. herdr can't read a popup's screen, so the card's text is
checked by the unit tests.

LH-227 settled it; LH-255 added the repo comparison.

## Why

A plugin action's output goes only to herdr's plugin log, so a popup pane
is the one place the human sees the answer. GitHub's head branch decides
first because it names the PR's author for certain; a report naming the
URL may come from a reviewer. Reports are the fallback for when GitHub
can't say, or for a member whose branch the ledger doesn't know. The
head repo is compared too, since unrelated repos share branch names like
`main` or `patch-1`. Falling
back to the clicked link keeps the handler from swallowing clicks it has
nothing to say about, as if it weren't there.
