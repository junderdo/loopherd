# D154

## Decision

The release installer (`install.sh`) takes no options (LH-545). It
supersedes D135's flags; the rest of D135 stands.

- **Arguments.** Any argument exits nonzero, before downloading anything,
  with `install: takes no options; it asks about each extra as it installs`.
- **Offers.** Every offer `--with-*` and `--no-extras` controlled is asked
  on `/dev/tty`, and `loopherd setup` always runs. Without a terminal each
  offer is skipped, as before, but its skip line says `run this installer
  again in a terminal to be asked` instead of naming a flag. `install.sh`
  sets that through `LOOPHERD_EXTRAS_NO_TERMINAL`; without it the shared
  offers keep naming `scripts/install`'s flags. A run pinned with
  `LOOPHERD_VERSION` to a release before this one uses that release's
  offers, which still name the flags; `loopherd update` is unaffected, as it
  runs the tag's own `install.sh`.
- **Environment.** `LOOPHERD_NO_SPLASH=1` replaces `--no-splash`;
  `LOOPHERD_VERSION` and `LOOPHERD_RELEASE_BASE` are unchanged, so
  `loopherd update`, which passes only environment variables, still works.
- **Unchanged.** `scripts/install` keeps all its flags: `loopherd update`
  (`--update`), lead installs and tests use them.

## Why

Options on a `curl | sh` installer are bloat: anything an option chose is
already a question the installer asks. A no-terminal run still installs loopherd and its
hooks, so automation loses nothing it relied on.
