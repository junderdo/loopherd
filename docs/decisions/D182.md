# D182

## Decision

A detached worktree (a lead's, a groomer's, any `worktree =` template's)
starts at origin's default branch every time, not only when created
(LH-450). Reusing one fetches, then moves it there with `checkout --detach`,
keeping untracked files. One with tracked changes or commits not on that
branch is refused, untouched, naming it.

## Why

`retire --close` keeps a worktree with uncommitted changes, so a later
`loopherd add <herd> groom` reused `groom-<herd>` at its old commit and
groomed against stale code. Refusing beats moving: a checkout would carry
tracked edits onto new code or strand the worktree's own commits.
