# D180

## Decision

A split that has to swap into place, left of or above its target, counts as
opened only when herdr reports the swap made (LH-479). Amends D138.

- **Unmade swap.** `pane swap` answers success with `.swap.changed: false`
  when it moves nothing (`not_found`, `same_pane`, `cross_tab`), so loopherd
  reads `changed` and treats false as a failed swap.
- **Plugin pane.** A view pane whose swap fails is closed and the open
  fails, as a shell pane's split already did. The view then falls back as
  for any failed split: beside the current pane, then the popup, whose note
  names the swap.
- **Refocus.** The pane the human had focused is focused again by ID with
  the socket's `pane.focus`, not through a neighbor.

## Why

A view left below or right of the shepherd at half size is the opposite of
the layout asked for, and its only report went to the plugin log while the
action said it opened beside the shepherd. A view already running can't be
handed a note, so closing it and falling back is the way to say why in the
view. The socket's `pane.focus` takes a pane ID; only the CLI lacks one.
