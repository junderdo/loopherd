# D180

Amends D57 and D143.

## Decision

A prompt that only carries what Claude made from finished background work
doesn't answer a lead's question or gate request, and doesn't clear D57's
pane label. Such a prompt is nothing but a sequence of these, separated by
blank space:

- a `<task-notification>` block, from its opening tag to a line that is
  exactly `</task-notification>`, as Claude sends for a finished background
  command or subagent;
- the same block under Claude's `[SYSTEM NOTIFICATION - NOT USER INPUT]`
  preamble;
- a subagent's or teammate's message: `Another Claude session sent a
  message:` then an `<agent-message …>` element closed by a line that is
  exactly `</agent-message>`, and the note Claude adds after it. A
  `SubagentHandback` report arrives this way.

Anything else counts, as before: a typed prompt, a `tell`, a raw relay, a
`<cross-session-message>` from a separate session, and human text that
quotes one of the shapes above with words before, between or after them.
The shepherd's self-restart (D91) reads prompts the same way: a prompt in its pane cancels it only when it is one a person sent.

## Why

On 2026-11-25 lead-loopherd-cards asked about PR #467 at 05:51 UTC, and its
wait was answered at 05:57 by nothing a person sent. The lead's transcript
shows the turn at 05:57:50 opened by a subagent's hand-back report, an
`<agent-message>` prompt, with the subagent's `<task-notification>` queued
behind it. D57's matcher took only a prompt that starts and ends with a
`<task-notification>` block, so the hand-back answered the question and
would have cleared the label.

UserPromptSubmit inputs captured from Claude Code 2.1.330 for a finished
background command and a finished subagent were each one bare block, so
those already kept the wait. The preamble appears in transcripts in front
of a block; it's accepted in case the hook sees it too.

- **Line-anchored closing tags over end-of-prompt:** a batch of blocks, or
  a block before a hand-back, has to be read one element at a time. The
  hand-back indents every report line, so a closing tag quoted in a report
  can't end the element early.
- **A teammate's message counts as background too:** Claude's own note says
  it was not typed by the user. A message from another session, which a
  human may be relaying through, still answers.
