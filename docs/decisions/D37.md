# D37

## Decision

`loopherd init` on a terminal (stdin and stderr both terminals) asks for
each value, showing the inferred one as its Enter default, as built in
LH-125 (D35 item 5):

- The order is repo, herd name, tracker (D36), GitHub `owner/name` (D40),
  checks, `max`, lead, the workers' `context_limit`, gh account, default
  branch, so every refusal that needs no gh call (an existing herd or lead
  prompt, a bad limit) comes before any gh call. On a terminal a taken herd name or an
  existing lead prompt is asked again; unattended it is refused, the lead
  prompt naming `--no-lead`.
- A flag answers its question, which is then not asked: `--herd`, `--repo`,
  `--check`, `--gh-account`, `--max`, `--no-lead`, `--context-limit`. An
  answer init can't take is shown with the reason and asked again.
- On a terminal, a repo another herd runs, or a herd file init can't read,
  ends init before the herd name is asked, since no name gets past either.
- Checks are suggested from build files, each one present adding its own:
  Cargo.toml gives `cargo fmt --check`, `cargo clippy -- -D warnings` and
  `cargo test`; package.json gives `npm run lint` and `npm test` for the
  scripts it defines, skipping npm init's always-failing placeholder test.
  On a terminal the human keeps them all, or keeps, drops or replaces each,
  then adds others.
- `max` defaults to 3 and must be a positive integer a herd file holds (i64). No lead writes no
  `[lead]` table, no lead prompt, and no `loopherd lead` step. An empty
  `context_limit` leaves it unset so `config.toml`'s default applies, and the
  question shows that value and where it comes from, naming the cap when 80%
  of the context window lowers it; one over 80% of the context window, or under
  10000, is refused naming the bound.
- Before writing, init prints a summary of the herd and asks to confirm,
  default yes; no writes nothing and exits 1.
- Unattended, flags and inferred values are used. Suggested checks count as
  inferred, so `--check` is needed only without a build file that suggests
  any; a value with neither (checks, an account matching no logged-in one,
  an origin that isn't GitHub, for a GitHub tracker; D40) is an error
  naming its flag.

## Why

The installer already asks this way, and a first herd's size and shape are
the choices a human most often wants to see before init writes them. Letting
a flag skip its question keeps one meaning per flag whether or not a
terminal is attached, and keeps scripts run without one unchanged. A
scripted call from a pty, such as a herdr pane, is on a terminal: it still
stops at the repo, default branch and confirm questions, which have no flag,
so feed it their answers (Enter takes each inferred value) or run it with
stdin not a terminal (`</dev/null`).
