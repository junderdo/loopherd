# D35

## Decision

How a user sets up a fresh repo for loopherd, settled with the human on
LH-122. LH-123 builds the first slice: `loopherd init` for GitHub, flags only;
the rest are their own cards.

1. Setup is both: `loopherd init` writes a valid default (structure: paths,
   account, queue, checks, switches); a shepherd then tailors the prose in
   init's files, guided by a "Setting up a project" skill section.
2. Tracker: init looks for the project's tracker doc; if none, it asks the
   human, default GitHub Issues.
3. The tracker stays shell snippets in the herd file; no `loopherd task`
   abstraction until a second backend.
4. Repo footprint: init writes repo files (an `AGENTS.md` section,
   `docs/agents/loopherd.md`, the tracker doc) and creates tracker labels; it
   never commits. Each write is skipped when already present.
5. Asking: terminal questions plus flags for unattended runs, as
   `scripts/install` does. Inferred values (repo path, owner/repo, the gh
   account matching the remote owner, default branch, check commands from
   build files) are shown and editable; unattended, a value init can't infer
   is an error.
6. Tracker doc: `docs/agents/issue-tracker.md` (mattpocock-skills'
   convention), plus `triage-labels.md` when present.
7. No doc: init asks GitHub (default) / local markdown / other and writes the
   doc in mattpocock's format itself.
8. GitHub and local markdown get built-in queue and check snippets; any other
   tracker gets a placeholder `source` that `loopherd herds` reports invalid,
   so the herd can't feed until the shepherd fills it from the doc.
9. Labels: mattpocock's vocabulary plus `blocked`. Claimable is open,
   `ready-for-agent`, and none of `blocked`, `needs-info`, `ready-for-human`.
   A worker stopped on a question sets `needs-info`. Names come from
   `triage-labels.md` when it exists.
10. GitHub checks: `merged` is a PR from the member's branch merged; `done` is
    the issue closed. The PR body carries `Closes #<n>`.
11. init writes `[lead]` (switches from `[lead_defaults]`, D31) and a lead
    prompt file; it prints `loopherd lead <herd>` and doesn't start it.
12. One herd per repo, named after the repo dir (overridable with `--herd`);
    init refuses when that herd name already points at another repo.
13. One built-in `issue` template; an optional label names the skill (`tdd`
    by default).
14. Branches are `<type>/<n>-<slug>`, the type from labels (bug→fix,
    documentation→docs, else feat), the map editable in the herd file.
15. Claim on GitHub: comment `claimed by <member>` and assign the issue to
    the gh account.
16. The human owns everything init wrote; loopherd never rewrites it. A
    re-run fills only what's missing and refuses to replace a herd file or
    lead prompt; `--diff` shows what today's built-ins would change. No hash
    tracking.
17. Agent step: init prints the next step; `loopherd --skill` gets "Setting up
    a project".
18. Trust dialog: init prints a reminder and never writes Claude's trust flag.

As built in LH-123: the skill label is `skill:<name>` (a name that, lowercased,
has anything but a-z, 0-9, `.`, `_`, `:` and `-` falls back to `tdd`); labels match whatever their case; the type map is a jq
object in the queue's `source`; `[lead]` writes all six switches with the
`[lead_defaults]` values init found (off where unset), so later default
changes don't reach an existing herd; every gh call runs as
`GH_TOKEN=$(gh auth token --user <account>)`; the default branch comes from
`gh repo view`. The herd name must be a lowercase letter then at most 26 of
a-z, 0-9, `_` and `-`, so `lead-<herd>` and `<herd>-<n>` are valid member
names; init refuses a repo that any herd file already points at. origin's
host matches `github.com`, `www.github.com` or `ssh.github.com` in any case;
`--repo <owner>/<name>` names the repo for any other origin, such as an ssh
host alias.

As built in LH-126: `docs/agents/loopherd.md` is filled with the herd's gh
account, default branch, checks and question label, and written only when the
file is missing. The `AGENTS.md` section counts as present when any ATX or
setext heading outside a code block (fences closing by CommonMark's rule)
names loopherd, in any case; otherwise init appends a `## loopherd` section
to the end, in the file's line endings, or creates the file with it. init
never writes through a link out of the repo: a symlinked `AGENTS.md`, live or
dangling, or a `loopherd.md` whose directory resolves outside the repo, gets
a printed step to write it by hand instead. A read-only `AGENTS.md` is
refused while planning, before the confirm and any gh call. The append comes
last, so a failed write undoes only the files and directories init created,
and a failed append truncates `AGENTS.md` back to its old length.

## Why

Hand-writing a herd file, lead prompt, tracker and repo docs from this
repo's examples was the only way to start, and those examples lean on
`scripts/trello`, which a fresh repo doesn't have. A command that writes a
valid default gets a repo to `loopherd feed --dry-run` in one step, and
keeping its output plain files the human owns leaves tailoring to the
shepherd and the human instead of a merge engine for upgrades.
