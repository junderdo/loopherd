# D87

## Decision

The plugin action `loopherd: open view beside shepherd` runs
`loopherd view --beside-shepherd`, which picks where the view opens:

- **Beside the shepherd.** When D82's `shepherd.json` names a pane on the
  herdr socket the action runs against, the view's plugin pane opens split
  `right` of it without focus and takes 40% of their width. A used record counts: after a resume the shepherd keeps
  its pane.
- **Beside the current pane.** Otherwise (no readable record, another
  herdr session's, or a split there that fails, as for a pane gone) it
  splits right of `$HERDR_PANE_ID`,
  the focused pane herdr gives every action, and passes the reason in
  `LOOPHERD_VIEW_NOTE`, which the view shows as a note until the first key.
- **Popup.** Only with no current pane either does it open the popup, with
  the same note.

The popup action is unchanged. The ratio is set by resizing the shepherd's
pane `right` after the split: herdr 0.9.5's `plugin pane open` takes no
ratio, and resizing the new pane instead moves an outer divider when the
shepherd already sits inside a split. A failed resize only warns: the view
is open by then. Trying the split, rather than first listing panes, leaves
no window for the pane to close in between.

## Why

LH-286. The human keeps the shepherd and the view together in one tab. The
record is written only at a handoff, so before the first one there is no
shepherd to find; a split beside the pane the human ran the action from is
closer to what they asked for than the popup, and the note says why it
landed there. The choice is made in loopherd, not the plugin's shell, so
its tests run against the fake herdr.
