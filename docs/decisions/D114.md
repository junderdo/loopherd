# D114

## Decision

Closes the gaps D95's Limits list for a `merge_guard = "credentials"` herd,
for its lead and, once D107's worker sandbox is built, its sandboxed workers
(LH-310, grilled with the human 2026-11-20). Amends D95, D105 and D107.

- **Credentials and open sockets are refused together.** `lead` and
  `revive` refuse a credentials lead whose herd sets `[lead] unix_sockets =
  "all"`, and `feed`, `add`, `spawn` and `revive` refuse a sandboxed worker
  whose herd sets `[worker] unix_sockets = "all"`, under `require` and
  `prefer`. `loopherd herds` marks the pair invalid, doctor fails on it, and
  the release notes name the change. With sockets open, the ssh agent, Git
  Credential Manager through WSL2 interop and the Secret Service keyring over
  D-Bus all authenticate as the human. D105's warning stays for herds without
  credentials.
- **Only the herd's own key in the config dir.** A credentials member's
  sandbox and file tools are denied reads of the whole config dir, with
  `allowRead` opening back `herds/`, `config.toml`, `trello.env`,
  `ssh/config` and the herd's own `credentials/<herd>.key`. Other herds' keys
  and tokens, every `sandbox/<member>.json` (each holds its member's token),
  the member's own token file (its token arrives as `GH_TOKEN`) and stray
  files dropped in the dir by hand all become unreadable. The build checks,
  as D95's probe did for `~/.ssh`, that `allowRead` carves files out of a
  denied directory on Linux.
- **No Windows drives on WSL2.** A credentials member is denied reads of
  every drvfs mount in `/proc/mounts` (`/mnt/c` and the rest): Windows ssh
  keys, `.git-credentials` and Windows gh's `hosts.yml` sit there. A list of
  Windows credential paths was rejected: it misses the next tool.
- **No inherited GitHub tokens.** The credentials `env` sets
  `GITHUB_TOKEN`, `GH_ENTERPRISE_TOKEN` and `GITHUB_ENTERPRISE_TOKEN` to
  empty beside `SSH_AUTH_SOCK`.
- **One deny set for leads and workers.** The read denies, allows and env
  are built by one function; LH-342 gives sandboxed workers the same set.
- **Workers must be sandboxed.** Once `[worker] sandbox` exists (LH-340), a
  credentials lead is refused unless its herd sets `[worker] sandbox =
  "require"`, and doctor fails on such a herd. Until then `lead` and `revive`
  warn that a credentials lead's workers run with the human's gh. Amends
  D107's doctor-only warning.
- **The watch and broker run a fixed `PATH`.** Both run outside the sandbox
  for a lead (D98, D104), so each sets `PATH` to a fixed value and runs `gh`
  and `git` by a path resolved from it, whatever the lead's command line or
  environment holds. A live probe records whether Claude Code still matches
  an env-prefixed `loopherd watch` (`PATH=… loopherd watch`) as excluded.
- **Setup and doctor read every page.** The deploy-key and ruleset listings
  in `merge-guard` and doctor paginate (`gh api --paginate`), so a repo with
  more than 30 of either doesn't get the key added twice or a duplicate
  ruleset.
- **Already closed:** `install = true` with credentials, refused since D95
  (PR 282).

## Why

- **A guard with the agent reachable guards nothing.** Each gap in D95's
  Limits ends in the human's own GitHub login, so the fix is to deny the
  reach or refuse the herd, not to warn. Warnings stay for what can't be
  closed.
- **An allowlist for the config dir,** because the files worth hiding there
  keep multiplying (keys, tokens, per-member settings holding tokens) while
  what a member needs to read is short and fixed.
- **Unsandboxed workers undo the lead's guard.** A hijacked lead can `tell`
  or `feed` an unsandboxed worker to `gh pr merge --admin` as the human
  (D89's and D98's noted hole), so a credentials herd sandboxes both or
  neither. That takes on D104's `.git/config.lock` placeholder for such a
  herd's workers, which the human accepted.
- **Refusing sockets costs `loopherd-cards` credentials for now.** Its
  workers need `unix_sockets = "all"` to reach the dev herdr in live tests
  (D107), so it can't be a credentials herd while they do. A path list in
  `network.allowUnixSockets` can't give them just that one socket: Linux
  and WSL2 ignore it (LH-363,
  [claude-unix-socket-allowlist.md](../research/claude-unix-socket-allowlist.md)).

## Limits

- **Other secrets in the human's environment** (e.g. `JIRA_API_TOKEN`) still
  reach a member; this decision covers GitHub only.
- **The member's own environment.** It can still unset `GIT_CONFIG_*` or name
  a URL the rewrite misses; with the gaps above closed, that reaches nothing
  the herd's key and token don't already.
- **`known_hosts`**, as D95 says.
