# D53

## Decision

A heredoc body that a sink writes only to files (`cat > notes.md <<'EOF'`)
is data even when the Bash call runs programs beyond D17's sinks, as long
as the script can't reach those files: no pipe or substitution passes a
command's output on, no function is defined, and every other command is a
reading sink, or an allowlisted inert program (`cargo`, `sort`, …) or
other sink whose words hold no quote, `$`, substitution or glob and no
written file's name. D17 lists both sets. Anything else keeps D17's rule, reading the body as
commands unless every command is a sink.

## Why

A reviewer subagent in a lead's pane was denied twice for writing review
prose with `cat > file <<'EOF'` beside `cargo fmt` (LH-193): one non-sink
command anywhere made the prose count as commands. A body that only lands
in a file runs only if something runs that file, so the hook looks for what
could: a name, a glob, a variable, a pipe, or a program that runs what
it's handed. An allowlist of inert programs replaced a first-cut denylist
of shells and builtins, which review showed leaked through `rbash`,
`python3`, `make -f -`, `script -c` and `compgen -C`. What it can't see, a file run by convention or
in a later call, is listed in D29's Limits.
