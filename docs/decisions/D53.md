# D53

## Decision

A heredoc body that `cat` or `tee` writes only to files with a prose
extension (`cat > notes.md <<'EOF'`), outside `.git` and `.cargo`, is data
even when the Bash call runs programs beyond D17's sinks, as long as the
script can't reach those files: no pipe or substitution passes a
command's output on, no function is defined, every other heredoc body in
the call is itself such a prose write, and every other command is a reading sink or an allowlisted inert
program (`cargo`, `uniq`, …) whose words hold no quote, `$`, substitution,
glob or brace and no written file's name. D17 lists the sets. Anything
else keeps D17's rule, reading the body as commands unless every command
is a sink.

## Why

A reviewer subagent in a lead's pane was denied twice for writing review
prose with `cat > file <<'EOF'` beside `cargo fmt` (LH-193): one non-sink
command anywhere made the prose count as commands. A body that only lands
in a file runs only if something runs that file, so the hook looks for what
could: a name, a glob, a variable, a pipe, or a program that runs what
it's handed. An allowlist of inert programs replaced a first-cut denylist
of shells and builtins, which review showed leaked through `rbash`,
`python3`, `make -f -`, `script -c` and `compgen -C`. A second round
showed the same call could still run the file by convention once named
`cargo-zz`, a git hook or a `build.rs`, so the file must carry a prose
extension and stay out of `.git` and `.cargo`; `chmod` and `sort` left the
inert list and `git apply` can no longer write a data body. A third round
ran the file from a second body written to `.cargo/config.toml` whose
runner reached it through a glob, which no name check on body text can
catch, so every other body in the call must be a prose write too. What it can't
see, a file run from a link or configuration made in a later or earlier
call, is listed in D29's Limits.
