# D173

Amends D100 and D107.

## Decision

D100's settings checks also read the main checkout's
`.claude/settings.local.json` when a lead's or worker's worktree is linked
from one (LH-428), beside the worktree's own two files.

- **Which main checkout.** The one the worktree's `.git` file names, read
  without asking git, as loopherd finds a repo's common dir elsewhere. A
  worktree that is itself the main checkout, or isn't a git checkout, adds
  no file.
- **What counts in it.** The permissions D100 counts in project and local
  settings. A `/` path in its `Edit(…)` rules starts at the worktree, the
  session's working directory, not at the main checkout where the file
  sits, as a bare path does.
- **The worktree's own local file stays read.** Claude Code still reads one
  an earlier version left there.

## Why

Claude Code keeps a worktree session's local settings at its main
checkout's root, so a `"permissions": {"allow": ["Write"]}` there, say from
a "don't ask again" approval in the human's session, reached a `require`
lead or worker that loopherd started without a finding. Claude Code's
permissions docs anchor local settings rules at the session's primary
working directory, so in a worktree session `Edit(/src/**)` from that file
matches the worktree's own `src/`, inside the member's own writes, and is
no finding.
