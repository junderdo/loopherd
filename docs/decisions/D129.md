# D129

Amends D65 and D126.

## Decision

`scripts/install` offers herdr key bindings for loopherd's plugin as a
fourth extra, after the herdr plugin, default no (LH-424).

- **When it asks.** Only on a terminal, with `herdr` on `PATH`, and with
  the plugin listed by herdr or just installed by this run. Otherwise it
  prints which case applies: no terminal, no herdr, or no plugin.
- **What a yes runs.** `loopherd install-herdr-keys`, which appends one
  `[[keys.command]]` entry (`type = "plugin_action"`) per action to the
  `config.toml` herdr reads (`$HERDR_CONFIG_PATH`, else
  `$XDG_CONFIG_HOME` or `~/.config`, then `herdr/config.toml`), as text,
  so every existing byte stays. It backs the file up beside itself first,
  like `install-hook`, and creates a missing one. `prefix+m` binds
  `loopherd.view` and `prefix+shift+m` binds
  `loopherd.view-beside-shepherd`, both unbound in herdr 0.9.5's
  defaults. `loopherd.status` gets no key: its output only reaches the
  plugin log. Each entry's `description` is what herdr's keybinds help
  shows.
- **Never overwrites.** An action already bound to any key is left alone,
  so a rerun changes nothing. A key the config binds, or a default that
  `herdr --default-config` lists and the config doesn't override, skips
  that action with a line naming what holds it. Keys compare as herdr
  reads them: modifier order and aliases folded, `prefix+M` the same as
  `prefix+shift+m`. An inline `keys.command` array is left for the human
  to bind by hand.
- **After writing** it runs `herdr server reload-config` when a server is
  running; a failure there, or of the whole step, is reported and the
  install goes on.
- **Flags.** `--with-herdr-keys` asks nothing else and, like the other
  extras, means just the extras named. `--no-extras` refuses beside it,
  `--remove` skips it, and `--settings` runs never touch herdr's config.
- **Removal.** `loopherd install-herdr-keys --remove` takes out only the
  entries whose command is a loopherd action with the description install
  gives it, leaving the rest of the file byte-identical. The README's
  hand-binding snippet uses another description, so a binding the human
  wrote from it stays.

## Why

D65 kept loopherd out of the human's herdr config and left the binding as
a README snippet; that made the view a hand-edit away. Opt-in, appending
as text, backing up and never taking a held key keeps the human in charge
of the file while removing the hand-edit. A user binding silently beats a
herdr default, so writing over a default's key would quietly take it away;
skipping it is the safe side.
