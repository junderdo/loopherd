# D18

## Decision

A new decision takes one past the highest D file on its branch. Two PRs that
both do so collide, and git flags it as an add/add conflict on
`docs/decisions/D<n>.md` and a content conflict on the index row in
`docs/wayfinding.md`. The PR that merges second renumbers while merging or
rebasing onto `origin/main`, in the existing conflict flow: its member keeps
main's D<n>, moves its own text to the next free number, fixes the index row and
every citation, and says so in a PR comment so the verifier rechecks the
citations. The member does it, not the lead or the shepherd. Nothing checks
open PRs for numbers ahead of time. The rule lives in
[agents/issue-tracking.md](../agents/issue-tracking.md).
(Since renamed to [agents/issue-tracker.md](../agents/issue-tracker.md), LH-130.)

Rejected:
- Reserving the number on the card: misses decisions found mid-card.
- Numbering at merge time: placeholders in code comments, and new machinery.
- Naming files by card: two schemes side by side, since D1–D17 stay.

## Why

The collision is rare, and git catches it every time, in a conflict the member
already has to resolve. Found by the lead's reviewer on PR #75 (LH-82);
grilled with the human 2026-11-03 (LH-85).
