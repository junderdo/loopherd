# D150

Amends D126.

## Decision

The herdr plugin offer hardens its update and its unattended runs (LH-423).

- **Update needs herdr 0.9.4.** Before offering `herdr plugin update`, the
  installer reads `herdr --version`. Older than 0.9.4, or unreadable, it
  asks nothing and prints the by-hand reinstall:
  `herdr plugin uninstall loopherd && herdr plugin install junderdo/loopherd/herdr-plugin`.
- **Runs without a terminal time out.** With `--with-herdr-plugin` and no
  terminal, `install`/`update` runs under `timeout 300` where `timeout`
  exists; a timeout is reported on stderr like a failure and the install
  goes on. On a terminal it runs bare, so Ctrl-C reaches herdr, which
  `timeout` would swallow.
- **Update is checked.** After an update the installer lists the plugin
  again: it prints the new version, or, when it didn't move, that herdr
  updates from the ref it installed, with the by-hand reinstall.

## Why

`plugin update` came in herdr 0.9.4 while the plugin allows 0.7.5, so an
older herdr was offered an update that always failed and was offered again
on every install. A hung clone or wedged server could stall an unattended
install after the binary and hooks were in place, which D126 claimed only
the list was safe from. And an update pinned to an old ref succeeded
without moving, so the next install offered it again with no hint why.
300 seconds covers a GitHub clone; the plugin has no build step.
