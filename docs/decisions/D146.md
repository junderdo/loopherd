# D146

## Decision

The view places the detail panel by what the herd tables need, not by a
fixed terminal width (LH-413):

- **Beside the list while the tables fit.** The list keeps its 55% share of
  the body, and the detail sits beside it while that share is at least as
  wide as the widest herd table's rows plus its borders. The strays panel
  doesn't count; its rows are free text, not columns.
- **Under the selected table when they don't.** Narrower, the list takes the
  full body width and the detail is drawn at that width just below the
  panel holding the selected row, pushing the panels after it down. Moving
  the selection to another herd moves it under that herd's table.
- **Scrolled in with the selected row.** The list scrolls far enough to show
  the whole detail under the selected row, but never past the selected row:
  a body too short for both keeps the row at the top and cuts the detail.
- **No box without a selection.** Before the first read, or with nothing
  listed, there is no detail panel at any width and the list takes the body.

## Why

- **A fixed width was the wrong measure.** The old 100-column threshold
  ignored the columns actually drawn, so a view in a side pane showed no
  detail at all, and a wide terminal could clip a long table beside it.
- **Below the selection keeps them together.** The detail describes one row,
  so the eye moves a line down rather than across a hidden pane.
- **An empty box only costs room.** Stacked, an empty detail would push the
  panels down for nothing; beside an empty list, it would push the quiet
  herd's sheep off centre.
