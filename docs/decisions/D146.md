# D146

Amends D88.

## Decision

When the shepherd's session-start rename (`herdr agent rename
"$HERDR_PANE_ID" shepherd`) is refused with `agent_launch_pending`, the
skill's Shepherd section has the shepherd read its own entry from `herdr
agent list` (the one whose `pane_id` is `$HERDR_PANE_ID`). If that entry is
already named `shepherd`, it carries on with no warning. Otherwise it
retries the rename once the entry's `launch_pending` clears, and a refusal
then is treated like any other error: it carries on and tells the human
`S` can't find it.

## Why

Seen on LH-412 (2026-11-21). A shepherd that `S` started runs under `agent
start shepherd`, so its pane already holds the name, but herdr refuses any
rename while the agent's startup is pending (`agent name cannot change
while startup is pending`). Read literally, D88's rule turned that refusal
into a false warning that `S` can't find the shepherd, when `S` had just
started it. Checking the name keeps the warning for the case it was meant
for: a shepherd started by hand whose name never took.
