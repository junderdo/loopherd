# D50

## Decision

`loopherd release <name>` marks a retired ledger entry released
(`released_at`), and `feed` (and the watch's `claimable`) treats a released
name as free, so its task spawns again once claimable. The new member's
record replaces the released one. Release is its own command, not a
`retire --refeed` flag: it acts on an entry already retired, often long
after, and retire's job is unchanged.

Release refuses an entry that isn't retired, naming it; a lead, which feed
never spawns; one recorded on another herdr session; and one whose tab may
still be open (`retire --close` first). It then clears the member's checkout
so the new member starts from origin's default branch: it removes the
recorded worktree (detached or not) and any worktree on its branch, and
deletes the local branch. When they hold commits not on the base it refuses
unless given `--keep-branch` (leave them; the new member continues from
them) or `--drop-branch` (delete them, printing each head sha). Whatever the
flag, it never removes a worktree with uncommitted or untracked changes or
mid-operation, and never touches the main checkout or a worktree a live
entry uses. A branch on origin is left alone, so the new member checks that
out. Rerunning release on a released entry clears and forgets again, so a
second run with `--drop-branch` finishes what `--keep-branch` left.

Release notes `released` in the member's mailbox, `status --all` shows the
entry as `<name> (released)` (and `released` in JSON), and it appends
`released: <name>` to its herd's lead's `watch-<lead>.fired`, which forgets
every key about that member: its own events and its checks' `failing` and
`recovered`. A lead may run it without a switch: it's part of feeding.

This amends D49's note that a retired name is never reused within a herd: a
released one is.

## Why

Feed skips every ledger name, retired or not, so a merged task whose card
is still open isn't spawned again; that protection stays for every entry
not released. A member retired before it finished (a tab closed by
accident, a rescoped card) had no way back but `loopherd add` by hand. An
explicit release keeps the default safe and makes re-feeding one command.
Clearing the branch by default gives the new member a fresh start, while
refusing on unpushed commits means work is only dropped when asked for, and
then with its sha printed. Without forgetting the watch's keys, a released
name would never be announced claimable again, and a stale `failing` key
would hide the new member's first failure.
