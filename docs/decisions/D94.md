# D94

## Decision

Amends D87's "still the shepherd" check. The handoff record in
`shepherd.json` also keeps `shell`: the pid and start time of the pane's
shell, as `herdr pane process-info` names it at the handoff, kept only
when it is the shepherd's Claude (`exec claude`) or an ancestor of it.
`loopherd view --beside-shepherd` counts the recorded pane as the
shepherd's while its shell is that process, whatever runs under it,
a bare prompt included. A record without `shell` keeps D87's check, which
also accepts a Claude that is the pane's shell.

The note names the cause: a pane with no shell pid (as while herdr
resumes its agent), a shell whose process can't be read, a shell that
changed, or (without a recorded shell) a Claude no longer under it.

## Why

LH-291. The record changes only at a handoff, so a Claude restarted in
its pane (`claude --resume`, a crash, an update) left a dead pid in it and
the view stopped finding the shepherd. The shell survives those restarts
and changes when herdr restarts. The shell comes from herdr, not from
walking up to the server, because a live herdr handoff reparents every
pane shell away from the server. A pane whose Claude was quit still holds
the shepherd's shell; the human may restart it there, and the next
handoff records wherever the shepherd runs.
