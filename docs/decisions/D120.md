# D120

Amends D114, D98 and D104 (LH-362).

## Decision

- **A lead's launch record keeps a `PATH`.** `lead` and `revive`, run by the
  human, record their `PATH` in `sandbox/<lead>.lead.json`, dropping empty
  and relative entries, entries D104 calls plantable (inside the lead's
  worktree or the state dir), and any in the temp dir or under a
  world-writable dir, which covers the sandbox's temp dir. `restart`,
  `--self` included, never rewrites the record: `--self` starts from the
  lead's own environment.
- **A lead's watch and broker run under it.** Both set `PATH` to the
  recorded value before starting anything, ignoring the `PATH` they
  inherit, so `gh`, `git`, the herd's checks and `after_merge` find what
  the human's shell finds and nothing the lead placed earlier on its
  `PATH`. The shepherd's own watch keeps its inherited `PATH`.
- **Older records keep today's behaviour.** A record without a `PATH`
  leaves the inherited one; `loopherd doctor` warns and names
  `loopherd revive --name <lead>`, after quitting its Claude, as the fix.

## Probe (Claude Code 2.1.330, Linux, 2026-11-21)

Headless `claude -p` with a lead's `excludedCommands`, allow rules and
`denyInsteadOfPrompting`, sandbox auto-allow on, and a fake `loopherd` that
writes outside the sandbox:

| Command | Result |
|---|---|
| `loopherd watch` | Ran outside the sandbox |
| `PATH=… loopherd watch` | Needed approval, so denied; still needed it with an allow rule naming `PATH=*` |
| `FOO=1 loopherd watch`, `env FOO=1 loopherd watch` | Needed approval, so denied |
| `FOO=1 loopherd watch` with a matching allow rule | Ran inside the sandbox |

The exclusion doesn't match an env-prefixed command, so neither form runs
outside the sandbox, and no variable reaches the watch from the lead's
command line. The `PATH` its pane's shell gives it still does; the recorded
`PATH` closes that.

## Why

- **The human's `PATH`, not a list of tools.** Checks and `after_merge` run
  arbitrary commands (`cargo`, `scripts/trello`); keeping the whole `PATH`
  finds them as the human's shell does, with no `[lead]` key to maintain.
- **Recorded where the lead can't write,** by commands only the human runs.
  Resolving at the watch's start would read the lead's `PATH`.
