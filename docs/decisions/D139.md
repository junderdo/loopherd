# D139

## Decision

`v` in the herd view switches the view and the shepherd between the two
`view.layout`s D138 defines, and saves the new one to `config.toml` as
`loopherd config set view.layout` would (LH-414).

- **Which shepherd.** The live agent named `shepherd`, and only when its
  pane is in the view's tab. With none there, or the view in a popup,
  nothing moves and the view says why.
- **Which way.** To the layout other than the saved one. A tab laid out
  by hand against the saved value takes one press to line up.
- **Moving without restarting.** The shepherd's pane moves; the view's
  stays put. herdr 0.9.5's `pane move` within one tab changes nothing
  (`reason: same_tab`), so the pane first moves to a tab of its own, then
  back with `--tab <view's tab> --target-pane <view> --split right|down
  --ratio <view's share>`. herdr removes the emptied tab. Both moves keep
  the pane's ID, terminal and processes. Left of the view takes a `pane
  swap` after, sourced from the view so focus stays on it, the ratio
  staying with the slot as in D138. The view keeps 40% either way.
- **Errors.** A herdr error at any step stops there, saves nothing, and
  the view notes it, naming the step. A shepherd stranded in its own tab
  keeps running; `S` still focuses it.

## Why

The human chose on 2026-11-21 that a key switch the layout and save it,
so the next open matches. Moving the shepherd rather than the view keeps
the view's TUI, which handled the key, in place.
