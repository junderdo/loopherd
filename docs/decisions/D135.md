# D135

## Decision

The release installer (`install.sh`) runs the same splash and offers as
`scripts/install` (LH-463), from bash files shipped in each release
tarball rather than ported into the `loopherd` binary.

- **Shared entry.** `scripts/install-extras splash` plays the splash;
  `scripts/install-extras offers <agents> <skills> <herdr-plugin>
  <herdr-keys> <loopherd> [<settings>]` runs the four offers, each `ask`,
  `yes` or `no`. `scripts/install` calls `offers` (it still sources the
  splash itself, so Ctrl-C keeps stopping it before the build).
- **Tarball.** Beside `loopherd`: `scripts/install-extras`,
  `scripts/install-*.bash`, `agents/` and `herdr-plugin/herdr-plugin.toml`.
  A release without them still installs and says it has no extras.
  Members are named without `./`, so an older `install.sh` still unpacks
  `loopherd` from a new tarball.
- **Terminal.** `install.sh` gives the extras `/dev/tty` when it opens,
  else `/dev/null`, so under `curl | sh` the questions are asked there and
  without a terminal each offer prints its skip line naming its flag.
- **Flags.** `install.sh` takes `--no-splash` (or `LOOPHERD_NO_SPLASH=1`),
  `--with-agents`, `--with-skills`, `--with-herdr-plugin`,
  `--with-herdr-keys` and `--no-extras`, meaning what they mean to
  `scripts/install`: naming an extra installs just those and runs no setup.
- **Needs.** The extras need bash and jq; without either, `install.sh`
  installs the binary and skips them with a line naming what's missing.
  A failed skills install no longer stops the herdr offers; it still
  fails the run after them.
- **Already installed.** The agent types, the mattpocock-skills plugin
  and the herdr plugin say they're already installed before any
  no-terminal skip, which costs a read-only `claude plugin list` or
  `herdr plugin list` on a run without a terminal.

## Why

The offers are about 400 lines of tested bash; porting them to Rust would
be a rewrite with the same behavior and a second copy to keep in step
until `scripts/install` moved too. Shipping the files keeps one copy that
both installers run. bash is already needed by `scripts/install`, and
where it's missing `install.sh` installs the binary and skips the extras.
