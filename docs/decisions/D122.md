# D122

Amends D42, D89 and D110.

## Decision

`loopherd update` brings an installed loopherd up to date, by whichever
path installed it (LH-400).

- **The install record.** Each installer writes
  `<config dir>/install.toml` in plain shell: `install.sh` writes
  `kind = "release"` and `tag`, `scripts/install` writes `kind = "source"`
  and `checkout`. The last install wins, so running the other installer
  switches paths. A `scripts/install --settings` run and an `install.sh`
  run with `LOOPHERD_RELEASE_BASE` write none, so tests never touch it.
  With no record, update refuses and names both installers; doctor warns
  about a missing record the same way.
- **Release path.** Update downloads the target release's own
  `install.sh` with `curl` or `wget` and runs it with `LOOPHERD_VERSION`
  pinned, so the fetch, `SHA256SUMS` check, rename, `install-hook`,
  `setup` and doctor stay in one installer. `--version vX.Y.Z` pins a
  release and is the only way to move to an older one.
- **Source path.** In the recorded checkout, update runs `git fetch`,
  then `git pull --ff-only` on the default branch, then
  `scripts/install --update`. It refuses a dirty tree, another branch
  checked out, or a pull that isn't a fast-forward, each time naming why
  and the manual `git pull && scripts/install`. `--version` is refused.
- **`--check`** reports and changes nothing: release, the current tag
  against the `releases/latest` redirect; source, the commits the default
  branch is behind. It exits 0 up to date, 1 behind, 2 when it couldn't
  check.
- **Up to date** prints `loopherd is up to date (<version>)`, exits 0 and
  changes nothing, `install-hook` included; a `--version` naming the
  current tag reinstalls it. Otherwise update first prints `vA → vB`, or
  `<old sha> → <new sha>, <n> commits`. It always replaces
  `~/.local/bin/loopherd`, saying so in one line when that isn't the
  binary running.
- **`scripts/install --update`** asks none of a fresh install's
  questions and shows no splash: agent types are refreshed by D26's rules
  only when `agents.sha256` exists (an edited one asked about on a
  terminal, else kept with a warning), a `claude plugin update` line is
  printed only when the mattpocock-skills plugin is installed, and plain
  `setup` runs, asking only for groups still unset. A human may run it
  after a manual `git pull`.
- **After the swap** doctor runs last, as in both installers. Brokers
  move onto the new binary by themselves (D121); update restarts none.
  When doctor finds the herdr plugin older, update prints
  `herdr plugin update loopherd` and doesn't run it.
- **It counts as `install`.** A lead may run it only with
  `[lead] install = true`. Otherwise loopherd refuses it in a lead's pane
  (a D110 row, reading the switch from the herd file), and the tool hook
  denies it under the `install` switch. With the switch on, the lead's
  sandbox runs a bare `loopherd update` outside the sandbox, as D89 does
  `scripts/install`. Workers are unaffected.

## Why

The human wants updating to be one command, instead of re-running the
one-liner or `git pull && scripts/install`, then restarting brokers. The
binary can't tell its own path: a clone at a release tag prints the same
bare `--version` as the release (D42), so the installers record it. The
record sits in the config dir because a sandboxed lead can write the whole
state dir (D89), and a source record pointing at a checkout it controls
would have the shepherd's next update run its `scripts/install`.

Running the release's own `install.sh` keeps one tested installer, lets
each release carry its own install steps, and adds no HTTP or archive
crate to the binary. A source update that pulls only fast-forwards on a
clean default branch can't lose the human's work. Restarting brokers is
D121's job, whose failures already leave a mailbox note and a doctor
warning. Re-asking nothing about extras keeps update quiet. Refreshing only
what's installed keeps it current, and the skills plugin is Claude's to
update. Counting update as `install` grants a lead nothing `scripts/install`
didn't.
