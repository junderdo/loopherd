# D88

## Decision

`S` in `loopherd view` brings up the shepherd: it focuses the live
shepherd's pane, or with none, splits the view's own pane `down` and starts
one there, so the view sits on top and the shepherd below.

- **Live shepherd.** An agent herdr names `shepherd`, or the agent in the
  pane `shepherd.json` (D82) records, when that record's socket is the
  view's herdr and its Claude process (PID and start time) still runs, so
  another agent later in that pane, or the pane's ID reused after a herdr
  restart, doesn't count. A used record still counts. Found, it's focused
  with `agent focus` and nothing starts.
- **Starting.** With none, the view splits `$HERDR_PANE_ID` down with
  `--no-focus`, in the plugin context's `workspace_cwd` (a plugin pane's own
  cwd is the plugin's root) or else the view's cwd, passing the view's
  `XDG_STATE_HOME` and `LOOPHERD_CONFIG_DIR` with `--env`, since a split
  pane doesn't inherit the caller's environment. Once its shell is at the
  prompt it runs `agent start shepherd --kind claude`, then focuses it. The
  herdr name is what a second `S` finds, until a herdr restart drops names.
  Any failure after the split closes the new pane, so a retry doesn't stack
  empty panes under the view.
- **First prompt.** When `handoffs/shepherd.md` was written after
  `shepherd.json`'s time, or there's no record, the shepherd resumes from it
  as D82's resume does: the record is marked used, the handoff moves to
  `shepherd.prev.md`, and the prompt is D82's resume text. Otherwise it gets
  the plain start: run `loopherd --skill` and follow its Shepherd section.
  A start that fails moves the handoff back and unmarks the record, so the
  next `S` resumes from it.
- **Popup.** A view without `$HERDR_PANE_ID` focuses a live shepherd, and
  otherwise says `no live shepherd; open the view as a pane to start one`.
- **Footer.** `S shepherd` is the last hint, after the toggles, so a narrow
  view cuts it before their state.

## Why

Asked by the human on LH-287 (2026-11-19), with the shepherd below the view
as the chosen layout. herdr splits only `right` or `down`, so the view must
exist first for it to sit on top. `s` and `a` toggle, and `t` switches theme
(D86), so the key is `S`.

Limits: a shepherd the human started by hand, with no `shepherd.json` yet
and no herdr name, isn't seen, so `S` starts a second one; so is any
shepherd after a herdr restart drops its name, until its next handoff
records its pane. The start runs on the view's reader thread, so reads
(and an Enter's focus) wait behind it, up to 30s for the new shell and a
minute for `agent start`; meanwhile the notes say `bringing up the
shepherd…` instead of calling herdr slow.
