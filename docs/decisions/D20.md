# D20

## Decision

A member (worker or lead) past its context limit hands off, and `loopherd
restart <name>` gives it a fresh session that resumes from the handoff.

- **Measure.** Tokens in context are `input_tokens +
  cache_creation_input_tokens + cache_read_input_tokens` of the last
  main-thread (`isSidechain` not true) assistant record in the Stop hook's
  `transcript_path`. No hook input carries a token count.
- **Limit.** The template's or `[lead]`'s `context_limit`, else
  `default_context_limit` in `$LOOPHERD_CONFIG_DIR/config.toml`, else 250000;
  never over 80% of that file's `context_window` (default 200000). The file
  is optional and rejects unknown keys; `loopherd herds` validates it and
  exits 1 naming it.
- **Fail safe.** When `config.toml` or the member's herd file can't be read
  or parsed, the check uses the built-in limit (250000 capped at 80% of
  200000, so 160000) and keeps checking, and leaves a `note` in the
  member's mailbox once per session (marked by
  `$XDG_STATE_HOME/loopherd/limit-noted/<session>`) naming the file and the
  error, which `watch` prints. Claude Code hides an exit-0 hook's stderr, so
  a warning alone would leave every member unchecked unnoticed (LH-94).
- **Trigger.** In a member's pane, from the member's own Claude, the Stop
  hook prints `{"decision":"block","reason":…}` once per session over the
  limit, remembered by an empty file at
  `$XDG_STATE_HOME/loopherd/handoff-asked/<session>`, written after the last
  handoff is moved aside so a failed move leaves the ask for the next stop.
  Any other failing check (such as a failed handoff move) warns on stderr
  and files the stop. Never on a
  `stop_hook_active` stop or a StopFailure. A blocked stop isn't filed, so
  watch sees no `finished` for it. The reason tells the member to save its
  work (a worker commits and pushes its branch and comments its progress on
  its task), write its handoff, report `--kind handoff` and end its turn.
- **Handoff file.** `$XDG_STATE_HOME/loopherd/handoffs/<name>.md`, outline
  State / Next steps / Gotchas, leaving out what the tracker, ledger or
  mailbox hold. The hook moves the last one to `<name>.prev.md` before
  asking again.
- **Watch line.** `<name> handoff <time> <text>`; a handoff counts as the
  report before a `finished`. Whoever reads the member restarts it: the
  shepherd restarts leads, unled herds' workers and herdless members; a lead
  restarts its workers. Amended by D78: a lead restarts itself with `loopherd restart --self`.
- **Restart.** Without `--force`, refuses unless the member reported a
  handoff since its last start, its last stop after that is `finished` with
  nothing in flight, and herdr shows it idle or done: a stop from before the
  handoff, or a prompt sent since, would otherwise let `/clear` queue behind
  a live turn. `--force` skips those checks only; a `/clear` sent mid-turn
  is queued until the turn ends and then drops whatever the handoff doesn't
  record. On the 30s timeout (a queued `/clear`, or no SessionStart hook)
  restart sends no handoff prompt, leaves the handoff in place for a retry,
  and prints a shell-quoted `herdr agent prompt` line to send once the pane
  shows a cleared session. Once the new session is confirmed, the handoff
  moves to `<name>.prev.md` and the prompt names that path, so no later
  restart, forced or not, resumes from a stale handoff. A lead's prompt
  also tells it to re-read status and reports and re-arm its watch. Always refuses with no handoff file, from the member's own
  pane (mid-turn; D78's `restart --self` waits for the turn to end instead), and for an entry without a herdr socket or in another herdr, since
  the SessionStart hook follows only an exact socket match. Sends `/clear` through herdr, waits up to 30s for the
  SessionStart hook to move the ledger to the new session, appends a
  `start` to its mailbox, then prompts "Read your handoff at <path>, then
  continue from it." Same pane, process, worktree and branch. Probed in
  `herdr --session loopherd-dev` on Claude Code 2.1.317: a prompted
  `/clear` runs as the command (new session id, the next prompt sees no
  earlier turn), so restart never exits Claude.
- **A lead's watch** is a background shell, so its stop after a handoff
  would read `paused`. Its reason and the skill tell it to stop its own
  watch before ending the handoff turn, keeping the finished rule, and to
  put re-arming it first in its next steps.
- **Only an exact socket match is asked.** A socketless ledger entry matched
  its pane id in any herdr, so the hook asks only a member whose recorded
  socket is the pane's. D21 since matches a socketless entry only from a
  caller without a socket, which is never asked either.
- **Limits** under 10000 tokens (`context_limit`, `default_context_limit`,
  `context_window`) are invalid config, naming the file.
- **After a revive**, the start makes restart refuse a member that handed
  off before it; the human forces it while the handoff file is there. A
  session asked before a crash isn't asked again; prompt it to hand off.
- **The shepherd** (LH-93) isn't a member, so no Stop hook measures it; its
  watch does. A watch run from no member's pane, as it exits, takes
  `$CLAUDE_PID` (counted only as an ancestor, as the hooks do), reads that
  Claude's session from `$CLAUDE_CONFIG_DIR/sessions/<pid>.json` (else
  `~/.claude`) when its `procStart` is the PID's start time, finds
  `projects/*/<session>.jsonl`, and measures it as above; a session any
  non-retired member holds is never measured, whatever pane matching says.
  Past the limit it adds `shepherd handoff <n>k over <limit>k` (thousands,
  rounded down) and, once printed, marks `handoff-asked/<session>` before
  releasing the watch lock; a timed-out watch prints it too and exits 0. Any failure is no line; a bad `config.toml` also
  warns. The limit is `[shepherd] context_limit`, else
  `default_context_limit`, else 250000, capped as above; `[shepherd]`
  rejects unknown keys and limits under 10000. The shepherd parks its work,
  writes `handoffs/shepherd.md` (spawn reserves the name `shepherd`), and gives the human one line to paste
  after `/clear`: `continue as the loopherd shepherd from <path>`. Amended by D82: `/clear` and any message resume it, with that line as the fallback. Probed
  on Claude Code 2.1.317: the sessions file's `sessionId` follows a
  `/clear`, and `procStart` is `/proc/<pid>/stat`'s start time.
- **Leads.** No new switch: the PreToolUse hook denies a lead's `loopherd
  restart --force` (plain `restart` is allowed).

## Why

Auto-compaction keeps a long-running member alive but drops detail at a
point it doesn't choose. A handoff the member writes itself, before the
window fills, keeps what matters and puts it where a fresh session reads
it. `revive` can't help, since `--resume` restores the same context;
PreCompact can't instruct the agent. The Stop hook already runs for every
member, and its block decision survives the installed command's `|| true`,
which swallows exit codes only. Facts:
[research/claude-context-limit.md](../research/claude-context-limit.md).
Grilled with the human 2026-11-03 (LH-92).
