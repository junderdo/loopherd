# D66

## Decision

The herdr plugin declares `[[events]]` hooks on `pane.agent_status_changed`,
`pane.exited` and `pane.closed`, each running `loopherd herdr-event-hook`.
The hook reads `HERDR_PLUGIN_EVENT` and `data.pane_id` (and
`data.agent_status`) from `HERDR_PLUGIN_EVENT_JSON`, maps the pane to the
non-retired ledger member on `HERDR_SOCKET_PATH` as `loopherd report` does,
and never calls herdr. Any other pane records nothing.

| Event | Mailbox |
|---|---|
| `pane.agent_status_changed` to `blocked` | a `blocked` entry, unless `<member>.block-recorded` exists; creates it |
| `pane.agent_status_changed` to `working`, `idle` or `done` | nothing; removes `<member>.block-recorded` and notify's `<member>.blocked`, so the next block is recorded and sent |
| `pane.exited` or `pane.closed` | a `gone` entry, unless one is there since the member's last `start` |

A watch's poll records what it sees: a member it saw go from not blocked to
blocked, through the same mark, and a member its two-poll check finds gone,
unless a `gone` is there from when this watch last saw it live (a member
back in its pane without a `start` can go again). A poll that sees a member
not blocked clears the mark, unless the mark changed since the poll's status
read. The watch prints `blocked` and `gone` only from unread mailbox entries
on its watch cursor, so each prints once, whichever of the hook and the poll
saw the change first. Several unread `blocked` entries of one member print
one line. They read and print as stops do: a lead's watch reads its
workers', the shepherd's the rest, and the lines keep their place after a
lead's check lines.

Limits, all of which a running watch's poll still covers:

- herdr runs each hook on its own thread, unordered. A `working` hook run
  after the `blocked` that followed it removes the mark mid-block, so a
  poll can record that block a second time; a `blocked` hook run after the
  `working` that followed it leaves a stale mark, so the next block
  between watches goes unrecorded.
- herdr runs at most 32 plugin commands at once and drops the rest.
- Closing a member's tab or workspace emits only `tab.closed` or
  `workspace.closed`, which carry no pane id, and the ledger doesn't record
  a member's tab, so the hook records no `gone` for it.

The live test this card asked for, which closes a member's pane on the dev
herdr with the plugin linked, is replaced by tests against the herdr fake
and the binary. herdr's plugin registry is global to the user, and linking
through the dev server registers it in the human's (D62).

LH-224 settled it.

## Why

Without the hooks, `blocked` and `gone` that happened between watches were
never replayed. Putting both the hook's and the poll's sightings in the
mailbox gives one reader path, with the watch cursor's exactly-once
printing, instead of reconciling two sources at print time.
