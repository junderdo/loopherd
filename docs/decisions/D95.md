# D95

## Decision

`[lead] merge_guard = "credentials"` is built as D83 describes, and a
`credentials` lead's git reaches GitHub through an ssh `Host` alias from
loopherd's own ssh config, which the human includes from `~/.ssh/config`.
Amends D85: `credentials` joins `hook` as a value, and a `credentials` lead
gets no merge alert.

- **Setup.** `loopherd merge-guard <herd>`, run by the human with their
  own gh login: makes the deploy key at `<config dir>/credentials/<herd>.key`
  if missing, adds it as a write deploy key unless GitHub lists it, creates
  or updates the rulesets `loopherd: default branch` and `loopherd: no
  force-push` by name, writes the herd's `Host loopherd-<herd>` block
  (HostName github.com, the deploy key, `IdentitiesOnly yes`,
  `IdentityAgent none`) into `<config dir>/ssh/config`, replacing an old
  one, and prints the steps loopherd can't take: the `Include` line, and
  the PAT made in the web UI and stored at `<herd>.token`.
- **The Include.** The human adds `Include ~/.config/loopherd/ssh/config`
  (their config dir) as the first line of `~/.ssh/config`, once for every
  herd. loopherd never writes under `~/.ssh`.
- **The lead's environment.** `GH_TOKEN` from the token file;
  `SSH_AUTH_SOCK` empty; and `GIT_CONFIG_*` clearing `credential.helper` and
  rewriting the repo's origin URL and its https and ssh github.com forms to
  `git@loopherd-<herd>:<slug>.git` with `url.insteadOf` and
  `url.pushInsteadOf` (which beats a `pushInsteadOf` of the human's). The
  settings file holds the token, so it is written 0600.
- **What the lead can't read.** `~/.ssh`, `~/.netrc`, `~/.config/gh`,
  `~/.git-credentials`, `~/.config/git/credentials` and
  `~/.cache/git/credential`, and the same under `XDG_CONFIG_HOME`,
  `XDG_CACHE_HOME` and `GH_CONFIG_DIR` when set, to the sandbox and the
  file tools, except that
  sandboxed commands (ssh) still read `~/.ssh/config` and `known_hosts`
  (`allowRead`).
- **Refusals.** `lead`/`revive` refuse a `credentials` lead without its key,
  its token or its sandbox, `prefer` included, or with `install = true`,
  whose `scripts/install` runs unsandboxed from a worktree the lead edits;
  `restart` refuses one running without its sandbox. Setup refuses a deploy
  key GitHub has read-only, naming the `gh repo deploy-key delete` to run.
- **gh on the lead's token.** For a `credentials` herd, `init` writes the
  `merged`, `done`, `source` and `backlog` checks as
  `GH_TOKEN=${GH_TOKEN:-$(gh auth token --user <account>)} gh`, and the lead
  prompt's gh lines plain. The lead's watch runs the checks sandboxed,
  where `gh auth token --user` reads nothing and would blank its
  `GH_TOKEN`; a human shell without one still runs as the account. The
  human merges from their own terminal with `--admin`. The token gets
  Issues: Read and write for a herd whose tasks are GitHub issues. Workers keep the
  `GH_TOKEN=$(gh auth token --user …)` prefix.
- **loopherd's ssh config** is written 0600 through a rename, since ssh
  refuses an included file others can write, which would break all the
  human's ssh. Writes take a lock and fail on a file they can't read
  rather than drop other herds' blocks. Keywords match as ssh reads them:
  any case, `=` or spaces.
- **Doctor** warns of a missing key or token, a `~/.ssh/config` that
  doesn't include loopherd's before its first `Host` or `Match`, a herd
  whose current `Host` block is missing, and rulesets that disagree with a
  herd's `merge`/`rebase`, including two herds on one repo.

## Limits

The split guards an honest lead fully and a hijacked one only partly. The
sandbox leaves these open, as D89 lists for writes:

- **Unix sockets**, closed by D105 unless the herd sets
  `[lead] unix_sockets = "all"`. With it, `allowAllUnixSockets` lets a lead point
  `SSH_AUTH_SOCK` at the human's running agent, and on WSL2 run a Windows
  credential helper such as Git Credential Manager by hand, either of which
  authenticates as the human. A Secret Service keyring, where gh keeps its
  token by default, is reachable over D-Bus the same way.
- **The lead's own environment.** It can unset `GIT_CONFIG_*` or name a
  URL the rewrite misses; that only matters through the gaps above.
- **Other herds' credentials** under `<config dir>/credentials/` stay
  readable.
- **Members** keep the human's credentials (D83 leaves workers out).
- **known_hosts.** A human who never used ssh with github.com has no host
  key for it, and the lead can't write one; run `ssh -T git@loopherd-<herd>`
  once.

## Why

- **The sandbox owns `GIT_SSH_COMMAND`.** Claude Code's sandbox sets it to
  plain `ssh` with its own ProxyCommand, overriding the settings' `env` and
  `core.sshCommand`, so a key can't be passed on the command line. That ssh
  still reads `~/.ssh/config`, so a `Host` alias is the one place the
  deploy key can be named; `%h` resolves to github.com for the proxy. This
  also made the planned `loopherd ssh-proxy` relay unnecessary.
- **Reads of `~/.ssh` must be denied,** or the lead pushes as the human with
  their default keys, reaching every repo they can push to. A live probe on
  Claude Code 2.1.329 showed `allowRead` carving `config` and `known_hosts`
  out of a `denyRead` on `~/.ssh`, and an empty `SSH_AUTH_SOCK` honoured.
- **An Include over a printed block.** The human edits `~/.ssh/config` once,
  and loopherd keeps every herd's block current in a file it owns, so a
  moved config dir or a new herd needs no second edit. Writing `~/.ssh`
  ourselves was rejected: it's the human's file.
- **No refusal at start for the ssh wiring.** Without the alias, git fails
  to resolve `loopherd-<herd>` and pushes nothing, which fails closed;
  doctor names it.
