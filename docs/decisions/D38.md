# D38

## Decision

`loopherd init --diff` (LH-129, D35 item 16) prints a unified diff from each
file init wrote to what today's built-ins would write, and changes nothing:
no file, no label. Its exit codes are diff(1)'s: 0 when every file matches,
1 when any differs, and 2 when it couldn't compare (not a git repo, a herd
file it can't read, a failed gh call), with the error on stderr and nothing
on stdout.

- It takes init's flags and infers the rest again, never asking: the herd
  is the one whose herd file runs this repo (else the directory name), and
  the tracker is GitHub when the repo has no tracker doc.
- Answers the herd file records are read back from it, a flag still
  overriding: a lead when it has a `[lead]` table, `[queue] max`,
  `[template.issue] context_limit`, and the checks listed in the worker
  prompt's checklist. With no herd file they take init's defaults, and
  checks the human reworded out of the checklist fall back to the ones the
  build files suggest.
- It needs read access only: an `AGENTS.md` init would append to is read,
  not opened for writing.
- The files are the herd file, the lead prompt, `docs/agents/loopherd.md`,
  `docs/agents/issue-tracker.md` when its title names a built-in tracker
  (GitHub or Local Markdown), `docs/agents/triage-labels.md`, and
  `AGENTS.md` when it lacks a loopherd section. A missing file diffs from
  `/dev/null`; each header is the file's path, the new side suffixed
  `(init now)`.

## Why

The human owns init's files and picks up improvements by hand (D35), so
`--diff` only shows drift; applying it stays theirs. Rendering with the
original run's answers, read back from the herd file, keeps a herd written
with `--herd`, `--no-lead`, `--max`, `--context-limit` or `--check` from
showing its own answers as drift. Exit 2 keeps a script's `|| notify` from
reading "couldn't check" as "drifted". A tracker doc with any other title was
written from a description init can't recover, so it has no built-in to
diff against.
