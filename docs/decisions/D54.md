# D54

## Decision

When the Stop hook first asks a member for a handoff in a session, it moves
`handoffs/<name>.md` to `<name>.prev.md` only if the file was last modified
before the member's last `start` in its mailbox (written by spawn, revive and
restart). A handoff written since that start belongs to this run and stays
where `loopherd restart` reads it. A member whose mailbox has no `start` has
its handoff moved, as before. LH-199 built it.

## Why

On 2026-11-17 a lead kept its handoff current as it worked, wrote it at
05:01:02, and stopped over its limit at 05:01:07. That was the session's
first ask, so the hook took the fresh file for last time's and renamed it to
`.prev.md`. The lead read the ask, judged its handoff "already current", and
reported `--kind handoff` without writing it again. `loopherd restart` then
found no `<name>.md`. Restart already moves a handoff aside once it has
resumed from it (D20), so the only stale `<name>.md` an ask can meet predates
the member's last start. The second `handoff-asked` marker from that night
(`0c8dcc21-…`, 05:02:43) was the shepherd's own watch marking its session,
not a Stop hook, and moved nothing.
