# D54

## Decision

The first time the Stop hook asks a member for a handoff in a session, it
moves `handoffs/<name>.md` to `<name>.prev.md` only if the file is last
time's. A file is last time's when its last change is at or before the
member's last context boundary in its mailbox. Two entries are boundaries:

- a `start` that began a fresh context, which spawn and restart write. A
  revive's `start` carries `"resumed":true` and is skipped, because
  `claude --resume` keeps the conversation.
- a `handoff` report, which means the file before it was already handed off.

A member with neither still has its handoff moved, as before. When the ask
moves a handoff it adds a line saying so and saying to write a new one, even
if the member thinks it is current. A tie counts as last time's, so a
restart refuses loudly instead of quietly resuming a stale file. LH-199 built
it.

Limit: the rule compares a file's modification time with timestamps from
loopherd's own clock. That assumes the state dir's times come from the same
machine. A network mount with clock skew could judge a handoff wrong in
either direction.

## Why

On 2026-11-17 a lead kept its handoff up to date as it worked. It wrote it
at 05:01:02 and stopped over its limit at 05:01:07. That was the session's
first ask, so the hook took the fresh file for an old one and moved it to
`.prev.md`. The lead read the ask, judged its handoff "already current", and
reported `--kind handoff` without writing it again. `loopherd restart` then
found no `<name>.md`.

A successful restart already moves a handoff aside once it resumes from it
(D20). A `<name>.md` can still be stale at an ask in two cases:

- spawn reused a name and found a leftover file. Spawn's `start` covers this.
- restart timed out before its rename, so no `start` was written, and the
  member was told to resume by hand. The `handoff` report covers this.

The second `handoff-asked` marker from that night (`0c8dcc21-…`, 05:02:43)
was the shepherd's own watch marking its session. It was not a Stop hook,
and it moved no file.
