# D74

## Decision

The `pane.moved` hook follows a member's pane to another workspace too. When
`data.pane.pane_id` differs from `data.previous_pane_id`, it sets the
member's `pane_id`, `tab_id` and `workspace` to the payload's new ones,
clears `workspace_label`, which the payload doesn't carry, and
keeps the pane id the agent was started with in a new ledger field,
`env_pane_id`, set on the first such move and kept through later ones. It
applies only while the entry still holds the payload's previous pane, tab
and workspace, so a late event for a place the member already left changes
nothing; a cross-workspace event missing either workspace id changes
nothing.

These lookups of a member by the caller's own `$HERDR_PANE_ID` accept
either `pane_id` or `env_pane_id`: `report`, the Stop and SessionStart
hooks, the PreToolUse hook's lead check, `restart`'s and `retire`'s refusals of a
member's own pane, and a watch telling a lead's run from the shepherd's.
Lookups by a pane herdr names in an event (`pane.closed`, `pane.exited`,
`pane.agent_status_changed`, `pane.moved`) match `pane_id`, the pane's
current id. Both ids are accepted because a restored herdr rebuilds each
pane's env with its current id, so after a restart the moved agent's new
shell and resumed Claude carry `pane_id`. `restart` keeps `env_pane_id`, since `/clear` keeps the
process; `revive` drops it when it resumes in a different pane, whose
shell has that pane's own id.

Closing the moved member's new pane, tab or workspace records `gone`;
closing its old ones doesn't. With no label, a revive finds the member's
workspace by its id, warning that no label is recorded. This amends D73's
limits: its cross-workspace limit is gone, and its other limits stand.

Limits:

- A move races the close of what it leaves: a move out of a tab it was
  alone in fires `tab.closed`, and out of a workspace it emptied also
  `workspace.closed`. Either hook reading the ledger before the move's
  writes it records a false `gone` (D73, LH-266).
- After a herdr restart reuses a workspace id, a new pane can take a moved
  member's old id, and an agent there resolves to that member through
  `env_pane_id`. A stale `pane_id` does the same. LH-271 tracks it.
- A workspace id reused after a restart can send a label-less revive to
  the wrong workspace, as for any entry recorded without a label.
- A moved lead's question labels no pane: `report` labels only a lead
  whose `pane_id` is the caller's `$HERDR_PANE_ID`.
- Other values the agent inherited stay stale too. A moved lead's `feed`
  or `spawn` with no `workspace` in its herd file spawns into the
  workspace `$HERDR_WORKSPACE_ID` names, its old one. `retire --close` run
  from a moved member's pane compares its `$HERDR_PANE_ID` with herdr's
  live panes and so can close the tab it runs in. A `restart` after a
  missed move hook records the live pane without keeping the old id.
  LH-269 tracks these.

LH-265 settled it, as the human's option A on LH-257.

## Why

A move to another workspace gives the pane a new id, but the agent's
processes keep the old one in `$HERDR_PANE_ID`. Keeping both ids lets the
event hooks find the member by the pane herdr names now while the agent's
own commands and hooks find it by the id they were started with, so a
moved lead keeps its guardrails and a moved worker's reports land.
