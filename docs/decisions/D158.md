# D158

## Decision

`loopherd init` offers the templates the human set up for loopherd-cards
(LH-556, the human's call on 2026-11-24), starting with groom; wayfinding
(LH-557) and grill-batch (LH-558) follow the same pattern. Amends D37's
question order.

- **Asked on a terminal.** After the default branch, init asks `Add a groom
  template, to triage unready tasks when the herd runs low?`, default yes.
  The summary shows the answer as `groom   yes` or `no`.
- **A flag without one.** Off a terminal a template is written only with
  `--with <name>`, which is repeatable and also answers the question on a
  terminal. An unknown name is refused by the argument parser, before
  anything is read or written. None is forced, unlike D148's grill.
- **The groom template.** `[template.groom]` has `params = []`, `name` and
  `worktree` `groom-{herd}`, `slot = false`, and no `done`, `merged` or
  `args`: it runs on the herd's args and the human's default model. It is
  never in `[queue] template(s)`; a lead or shepherd starts it with
  `loopherd add <herd> groom` on `running low` (D60, D116). Its prompt
  defers to `loopherd --skill --section groom` for rights, limits and the
  report, lists the unready tasks with the command `loopherd herd get {herd}
  queue.backlog` prints, gives the batch-line forms for mark ready, needs
  spec (a comment) and close in the tracker's own commands, and reports
  through a quoted heredoc.
- **Per tracker.** GitHub's forms are `gh issue edit --add-label`, `gh issue
  comment` and `gh issue close`, run as the herd's account. A local
  tracker's forms edit the issue file in the repo's checkout, but only on an
  up-to-date default branch, commit it and push it. Another tracker's are
  `(fill in)` lines.
- **`init --diff`** reads a `[template.groom]` back from the herd file and
  renders it again; `--diff --with groom` shows the one init would add.
- **No merged-check warning.** `loopherd herds` no longer warns that a
  template has no merged check when it has `slot = false` and no `done`:
  such a member is retired by hand, never after a merge.

## Why

Every new herd runs low sooner or later, and the groomer is how
loopherd-cards keeps its backlog moving, so a new herd should get it for one
keypress. Asking on a terminal and taking a flag otherwise keeps a scripted
init's output unchanged, and leaves out a template a herd may not want.
