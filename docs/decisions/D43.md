# D43

## Decision

`loopherd herd remove <herd>` deletes a finished herd completely: its herd
file, its pause file, its `[lead]` `prompt_file`, and each member's ledger
entry, mailbox (`reports/<name>.jsonl`) and handoffs (`handoffs/<name>.md`
and `<name>.prev.md`). The herd then leaves `herds`, `status --all` and
`stats`.

- It refuses, changing nothing, while any of the herd's ledger entries,
  lead included, is not retired, or is retired but herdr still shows its
  agent or tab open, and prints a command that clears each, with why.
  Retired is not enough: `retire` without `--close`, a tab close that
  failed after retiring, or a lead retiring itself all leave a running
  pane behind, and removing its entry would leave nothing `retire --close`
  could clean it up from. The tab is found as `retire --close` finds it
  (by agent name, else the recorded pane in its workspace and cwd).
  Anything short of closed counts as open: a pane at its prompt whose cwd
  moved, a pane running a command, and a workspace not found by its label
  while the recorded pane is in some other workspace (as after a
  relabel).
- Counted as closed: a workspace gone with the pane in no workspace, and
  a recorded pane, with no live agent by the member's name, that is
  provably another's. It is another's when another entry holds it, when
  it runs an agent from another session, or when its tab isn't labeled
  with the member's name, since spawn and revive always label it so and
  a restart can hand the pane id to a new workspace's tab
  (`docs/research/herdr.md`). The label is checked before the pane's cwd
  or whether it is busy, and an agent of the member's own session in the
  pane overrides it, so a renamed tab the member still runs in stays
  open.
- Trade-off: a label is not proof. A member's tab the human renamed,
  with its session gone, counts as closed, and its entry goes while the
  tab and worktree stay for the human. Requiring a second signal would
  break the `herdr tab rename` way out below, and a reused pane in a
  workspace reusing the old label would refuse with no way out but
  closing the human's tab.
- The command a refusal names:
  - `loopherd retire --close <name>` for an entry not retired, or whose
    tab `retire --close` would close.
  - `herdr tab close <tab>` for a tab `retire --close` keeps (busy, split,
    outside the recorded workspace or cwd, or no tab matched). Where the
    tab may not be the member's, it adds `herdr tab rename <tab> <label>`;
    where another session holds the name, `herdr agent rename <name>
    --clear`. Either alternative makes the rerun go through.
- An entry recorded on another herdr socket than the one this run talks
  to is refused without asking herdr, since this session can't see its
  tab; an entry with no recorded socket is looked up in this session.
  When herdr can't be reached it refuses too. A herd with no ledger
  entries never asks herdr. There is no `--force` that retires for you.
- It never touches worktrees, branches or herdr tabs: that stays
  `retire --close`'s job.
- The lead's `prompt_file` goes only when it resolves inside the herds
  dir and no other herd file names it, as its lead's or any template's
  `prompt_file`. A herd file that can't be parsed counts as naming it.
  A kept prompt gets a `kept <path>: <why>` line.
- Ledger entries go through a new `Ledger::remove_herd`, which re-reads the
  ledger under its lock, re-checks that every entry is retired, and deletes
  the mailboxes and handoffs of exactly the names it removes while holding
  the lock, saving nothing if a delete fails. A concurrent write survives,
  and a name reused by another herd meanwhile keeps its files. With
  `--keep-history` each member's handoffs are deleted under the lock too,
  only while its entry is still a retired member of the herd.
- It removes the herd's runs, not just its entries (LH-233). A run of the
  herd archived in another entry's `earlier` (D51, spawn over a retired
  member) goes too, and that entry stays. An entry of the herd whose
  `earlier` holds runs of other herds keeps them: the newest becomes the
  entry, retired, with the older ones as its `earlier`, so their herds
  stay in `stats`. A name keeps its mailbox and handoffs while any of its
  runs stays, and each such entry gets a `removed <herd>'s runs from
  ledger entry <name>; its other runs stay` line (`kept <herd>'s runs in
  ledger entry <name>` with `--keep-history`). A herd known only by
  archived runs counts as known. A promoted run keeps its
  `released_at`; when it was unreleased, its name is taken for `feed`
  again until `loopherd release`.
- It refuses, changing nothing, when `reports/` or `handoffs/` is a
  symlink, so it never deletes outside the state dir. A file it can't stat
  is an error, not read as absent, and every file is statted before any
  is deleted. A `[lead]` `prompt_file` that isn't a
  regular file is kept.
- Every line for what it already removed is printed even when it then
  fails.
- A herd known only by ledger entries (no herd file) or only by its file
  (no entries) is removed too; one with neither is an error.
- `--dry-run` prints every path and ledger entry it would remove.
  `--keep-history` keeps the ledger entries and mailboxes, so `stats`
  still counts them, and removes the rest.
- Order: members' files, then ledger entries, then the pause, prompt and
  herd file last, so a run that fails partway can be rerun: the herd is
  still known by its file or its entries.
- The PreToolUse hook denies `loopherd herd remove` in a lead's pane
  whatever its switches, as for `herd set` (D29).

## Why

Removing the old `my-app-prs` herd took a hand `jq` edit of `ledger.json`
under `flock`, which is easy to get wrong while other writers run. Refusing
live members keeps removal from stranding a running agent with no ledger
entry. Leaving worktrees and tabs to `retire --close` keeps one command
responsible for cleaning up a member's checkout, with its clean-and-merged
checks. Herd files are the human's, so a lead may not delete its own.
