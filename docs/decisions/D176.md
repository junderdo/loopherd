# D176

## Decision

LH-440. When a lane's own read of the ledger fails just before it carries a
request out, the request waits: the lane leaves it queued, with no reply and
no start mark, and a later round reads the ledger again and decides it. A
read that finds the lead retired still refuses it, and one that finds it
unretired runs it.

## Why

- **Refusing would turn a passing read failure into a lost request.** The
  lead is most likely still unretired, and a waiting request costs one poll.
- **Running it breaks the lane's promise** that a request written after a
  retirement is refused: the round's read and the listing's reread can both
  predate the retire.
- **Waiting is already how the lane handles a restart's stop**, and the lead
  can still withdraw a request it gave up on, since it is never marked
  started.

## Limits

- **A ledger that stays unreadable** holds the request unanswered until the
  lead's client gives up on it, the same as a broker that isn't running.
