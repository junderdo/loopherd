# D174

## Decision

`loopherd init` offers a `grill-batch` template and routes the queue to it
(LH-558), the third of D158's templates, after D167's wayfinding. Applies
D132's batch grill to init's own herds.

- **Asked after wayfinding.** On a terminal: `Add a grill-batch template,
  so grilling tasks marked for batch mode run unattended?`, default yes,
  with a two-line explanation above it. Off a terminal only
  `--with grill-batch` writes it. The summary shows `grill-batch yes` or
  `no`.
- **Routed by `grilling` and `grill:batch`.** A task with both goes to
  `grill-batch` as type `docs` with the `grilling` skill, ready label or
  not; it wins over a wayfinding label. A `grilling` task without
  `grill:batch` waits for a live grill: the source leaves it out, ready or
  not, and `backlog` keeps it. GitHub's source swaps `--label` for
  `--search 'label:"<ready>","grill:batch"'`, which keeps gh's 1000-issue
  window to candidates, and picks the claimable ones in jq; a local tracker reads the same words on
  the `Status:` line; another tracker gets the rule in the comment beside
  its empty `source`. `templates` lists `issue`, then `wayfinding` and
  `grill-batch` as the herd has them.
- **Without it, nothing changes**: the source and backlog init wrote
  before, wayfinding's routing included (golden tests hold both), so the
  migration below finds an older herd's `[queue]` init's own.
- **The template** takes the issue template's `params` (the queue routes
  to it) and its `context_limit` and `merged`, with `name`
  `{herd}-grill-batch-{number}` (local `{id}`), branch `docs/{number}-{slug}`,
  and its prompt in `<herd>-grill-batch.md` beside the herd file, which
  init refuses to replace. Its `done` passes once the task is closed or
  open and `needs-info`: a member whose batch waits on the human is reaped.
  Another tracker's `done` is left to fill in, and init's next steps say
  so.
- **The prompt** reads the task, answers the grill's questions itself
  (the `grilling` skill in batch mode), posts one `Batch grill <key>, round
  <k>` comment, reports a question, marks the task `needs-info` and stops.
  A later member reads the human's reply after the latest round: `discuss
  <n>` or an override that moves another pick posts the next round;
  `accept all` writes the decision, files its issues and hands in as the
  grill does. A local issue's batch is committed on the default branch,
  leaving the member's branch untouched, and a local member doesn't claim,
  as claiming commits.
- **Labels, lead and docs.** GitHub creates `grilling` and `grill:batch`
  where missing. The lead prompt's "Grilling is always the human's."
  becomes the batch-grill exception, and the tracker doc and
  `docs/agents/loopherd.md` get a `## Batch grills` section saying how the
  shepherd releases a waiting batch.
- **Names fit 32 characters.** `-grill-batch` is 12 characters, so a
  GitHub or other herd with it takes a name of at most 13; a local source
  cuts the id to fit, and skips the issue, saying why, only when it can't.
- **The `grill-batch` migration** (D157) offers an existing herd the
  template, its prompt file and its routing together, under D167's rule:
  applied only where `[queue]` is what init writes without it, else shown.
  It doesn't touch the lead prompt or the docs.

## Why

D132 settled how a batch grill runs on loopherd-cards; a new herd should
get it for one keypress, with the same release step. Routing grilling
tasks by label lets the human pick batch or live per task without a
second queue.
