# D174

Builds D157's init re-run (LH-566).

## Decision

`loopherd init` in a repo whose herd exists re-asks that herd's settings
in place.

- **Keys are edited as keys.** `max` and `context_limit` change through
  toml_edit, keeping the file's comments, layout and line ending, and are
  asked whenever their table exists. A missing `[queue] max` or
  `[template.issue]` skips its question with a line naming where to edit.
  A `context_limit` a later config.toml put over the cap is kept on Enter.
- **Text settings are re-rendered.** Checks, gh account and default branch
  live in prose and commands, so init renders the herd with today's init
  from what the herd file records (leaving out the grill template when the
  herd has none), renders it again with the new value, and carries each changed run of lines into the herd's files.
  A run is carried only where it appears in the file as often as in the
  rendering; otherwise the setting is "not init's own" and is skipped with
  one line, never guessed at.
- **"Init's own" is probed before asking.** The same carry with a probe
  value decides whether the question is asked at all. Checks also need
  every checklist item to be a bare `` `cmd` ``. Enter keeps a gh account
  gh has since logged out of; only a changed one is checked against gh.
- **merge_guard is asked of a lead with merge off.** Switching to
  `credentials` also rewrites every gh command's token and requires
  sandboxed workers, so it is carried as text, as a fresh init writes it,
  or skipped with a line saying what to set by hand. Back to `hook`, the
  key alone changes when the text can't be carried.
- **Adding a lead** appends init's `[lead]` table, as a hook lead's, to
  the herd file and writes the lead prompt; a `credentials` answer is then
  offered as its own switch. It is skipped when a prompt file already sits
  at the herd's lead prompt path.
- **Writes** go new files first, then the herd file through the checks
  `loopherd herds` makes (the new files removed if it is refused), then
  the prompt files it changes; each refuses a file changed since it was
  read.
- **Refused on a re-run:** `--tracker`, `--repo`, `--no-github` and
  `--with` (what makes a new herd), `--no-lead` on a herd with a lead, and
  a herd file `loopherd herds` calls invalid, which is fixed first.
- Each changed answer shows its diff and asks `Apply? [Y/n]`; without a
  terminal, a flag's change is applied and shown. The migration offers
  that follow are `loopherd herd upgrade`'s own.

## Why

A tailored herd is the common case (D157), so a re-run that re-wrote whole
files would undo the human's edits. Keys have a structural home; prose
doesn't, and loopherd never kept the text it first wrote, so re-rendering
is the only way to know which lines a setting owns. Probing before asking
keeps a question from being asked whose answer couldn't be applied. An
invalid herd can't pass the checks every write makes, so refusing it up
front beats refusing each answer.
