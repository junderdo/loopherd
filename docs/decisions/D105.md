# D105

## Decision

Amends D89, D95, D98 and D100. A sandboxed lead gets no Unix sockets. On
Linux and WSL2 Claude Code's seccomp filter blocks them where it's present,
and the filter check below finds where it isn't (LH-303). On macOS Seatbelt,
the sandbox built into the OS, blocks them with no seccomp, so the check
counts them blocked there without probing.

- **Default: none.** A lead's generated settings set
  `sandbox.network.allowAllUnixSockets: false`, explicitly, so the human's
  own settings can't turn it on (`--settings` outranks them). Its herdr
  calls go through its broker (D98) or its unsandboxed watch (D104), so it
  needs no socket. Run inside the sandbox, `herdr` fails with
  `Operation not permitted`.
- **Opt-in: `[lead] unix_sockets = "all"`.** Unset means none; any other
  value makes the herd file invalid in `loopherd herds`, which shows the
  value beside the lead's switches. It restores `allowAllUnixSockets: true`
  and is allowed under `sandbox = "require"`. The lead still uses its
  broker. `lead`, `revive` and `loopherd doctor` warn that it reopens the
  herdr socket, the human's ssh agent and WSL2's Windows interop; doctor
  adds when interop is enabled on the machine
  (any `/proc/sys/fs/binfmt_misc/WSLInterop*` entry that reads `enabled`,
  such as newer WSL's `WSLInterop-late`; LH-337). A lead can't set it: the tool
  hook denies `loopherd herd set` in its pane. One honestly named switch,
  not a separate `windows_interop` one: the human chose it.

- **Filter check.** On Linux and WSL2, `lead`, `revive`, `loopherd doctor` and
  `loopherd setup` probe whether the sandbox really blocks a Unix-socket
  connect: they run `socat UNIX-CONNECT` against a socket loopherd binds,
  under each seccomp filter Claude Code could use: `claude` by its PATH
  name with `ARGV0=apply-seccomp` (the native binary's own, which a
  version manager's shim passes on), then
  `vendor/seccomp/<arch>/apply-seccomp` beside an npm install or in the
  global `@anthropic-ai/sandbox-runtime`. Only socat's own denial counts
  as blocked; the filter's setup errors (`apply-seccomp: …`, such as
  AppArmor refusing it user namespaces) also end in
  `Operation not permitted` and count as open, with their own fix. No API
  call: a claude that doesn't dispatch on `ARGV0` exits on socat's options. When it
  doesn't block, and the herd hasn't set `unix_sockets = "all"`, the
  lead's start follows D100's rule for a loosened sandbox: `require`
  refuses it naming `npm install -g @anthropic-ai/sandbox-runtime`,
  `prefer` starts it with a warning, a mailbox note, the ledger's
  `sockets_unblocked` and `(lead, sockets open)` in status, and a
  `credentials` lead is refused under both, since the ssh agent stays
  reachable. Doctor fails when some herd's lead would be refused, else
  warns, and names each running lead started so. `scripts/install`
  shows doctor's line; `loopherd setup` prints a note. Neither installs
  the package.
  A lead can clear `sockets_unblocked` in its own ledger entry; doctor's
  sandbox check still reports the machine.
- **Restart.** `restart` holds a lead recorded `sockets_unblocked` to the
  same rule, judged against the herd's current switches: `require`
  refuses it, `credentials` refuses it under both modes, `prefer` warns,
  and `unix_sockets = "all"` lets it through. The refusal names `revive`,
  whose fresh probe names the fix (LH-338).
- **Which `claude`.** The check resolves `claude` from loopherd's own
  PATH, while herdr starts the lead's Claude from the herdr server's PATH.
  Where the two differ, the check can test a different Claude Code than
  the lead runs. Under a mise or asdf shim, the native filter is still
  reached, since the shim passes `ARGV0` on, but the npm lookup beside
  `claude` looks in the shim's directory, or the version manager's own for
  a symlinked shim such as mise's, and finds no helper there; only the global `npm root -g` lookup can find one.
  Run loopherd and herdr from the same environment (LH-338).
- **Probe cost.** Each command the check runs (`claude --version`,
  `bwrap`, `npm root -g`, each filter) is killed after 10 seconds, with
  anything it forked that still holds its output, and counts as failed. `npm root -g` runs only when the native filter didn't
  answer, and one `revive` probes once, however many leads it starts
  (LH-338).
- **macOS's socket allow-list.** `sandbox.network.allowUnixSockets` in the
  human's settings merges into the lead's and reopens the paths it lists
  on macOS, so it is a loosening switch (D100): `require` refuses it and
  `prefer` warns. An empty list opens nothing and doesn't count (LH-337).
- **Credentials behind a socket.** A `hook` lead runs gh and git with the
  human's own credentials, so any that live behind a Unix socket are out
  of its reach: gh's token in the Secret Service keyring (D-Bus), an ssh
  remote's key in the agent (`SSH_AUTH_SOCK`), and Git Credential Manager
  reached through WSL2 interop (D95, D114), so its gh calls and its pushes
  fail to authenticate. Keep gh's token in its `hosts.yml`
  (`gh auth login --insecure-storage`) or `GH_TOKEN`, give origin an https
  remote, and make gh git's credential helper (`gh auth setup-git`); `store`
  also works, but GCM, `cache` and libsecret sit behind a socket. Or use
  `merge_guard = "credentials"`, whose deploy key and token need no socket. Nothing warns of it ahead of time; the first
  failing call shows it (LH-337).
- Not tested here, since this machine always has the filter: whether
  `failIfUnavailable` notices it missing. The binary's own message
  (`apply-seccomp binary not available - unix socket blocking disabled`)
  suggests it starts without blocking, so loopherd checks for itself.

## What the experiment showed

Tried on WSL2 with Claude Code 2.1.329 installed as its native binary and
`@anthropic-ai/sandbox-runtime` not installed, running a probe through
`claude -p` under each setting:

| From the sandbox | `allowAllUnixSockets: false` | `true` |
|---|---|---|
| `connect()` to a Unix socket | `EPERM` | connects |
| `herdr agent list` | `Operation not permitted` | lists |
| `cmd.exe /c ver`, `wsl.exe -e true` | fail: `UtilBindVsockAnyPort: socket failed 1` | run |

- The research said only the npm package's seccomp filter blocks sockets.
  The native binary carries its own: it runs an embedded `apply-seccomp`
  (selected by `ARGV0=apply-seccomp`). An npm-installed Claude Code still
  looks for the package's `vendor/seccomp/<arch>/apply-seccomp` in the
  global install, and runs without blocking when it's missing.
- WSL2 interop dies with the block: the filter refuses `AF_VSOCK` as well
  as `AF_UNIX`, and `/init` needs a vsock before it reaches
  `$WSL_INTEROP`'s socket. Unsetting `WSL_INTEROP` alone wouldn't do.

## Why

herdr has no auth, so its socket gives every pane to whoever reaches it
(D98's Why), and the setting that opened it also opened the ssh agent and
WSL2 interop: each a way out of the sandbox, and the agent and Git
Credential Manager a way to act as the human (D95's limits). With the
broker carrying the lead's herdr calls, nothing the lead needs uses a
socket.

## What remains

- Workers run unsandboxed (LH-284), so a lead can have one do what its
  sandbox refuses.
- The state dir is still mostly writable to a lead (LH-298).
- MCP servers a herd names and the human's own settings (D100).
- Any socket, under `unix_sockets = "all"`, and every socket where the
  filter check finds no filter and `prefer` starts the lead anyway.
