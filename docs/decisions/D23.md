# D23

## Decision

The human pauses a herd with `loopherd pause <herd> [--reason <text>]` and
resumes it with `loopherd resume <herd>`; both take `--all` in place of a
herd, meaning every herd file that exists now. The shepherd runs them when
the human asks in prose. Pausing writes
`$XDG_STATE_HOME/loopherd/paused/<herd>` holding the time and the reason;
resuming deletes it. `--all` writes one file per herd, so a herd added later
starts unpaused and `resume <herd>` lifts one herd alone. Pausing a paused
herd keeps the first time and replaces the reason only when one is given;
resuming an unpaused herd says so and exits 0; a herd with no herd file is
refused, as `feed` refuses it. Neither command prompts anyone. `resume`
prints the next step: for a led herd that its lead's watch sees claimable
tasks within 60s, for an unled one to run `loopherd feed <herd>`.

**Paused means no new workers.** In-flight workers carry on; verifying,
merge questions and after-merge steps go on as before, so a paused herd
drains by itself. Nobody is interrupted.

- `feed` still retires and closes members whose `done` passes, spawns
  nothing, and prints `<herd> paused since <time>: spawned nothing`.
  `add` and `spawn` still work: they are deliberate, not the queue.
- A lead's watch prints no `claimable` for a paused herd; `merged`, reports,
  stops, `blocked` and `gone` print as before.
- The PreToolUse hook (`loopherd tool-hook`, D17) denies `loopherd pause`
  and `loopherd resume` in a lead's pane, always: no switch turns it off.
- `status` and `view` show the herd as `<herd>  paused since <time> —
  <reason>`, `status --json` carries a `paused` object (null when not), and
  `herds` gets a `paused` column. Pending merge questions stay in the
  mailbox and are relayed as now.

Bringing members back after a herdr or machine restart stays `revive`'s
(D8), not resume's. A pause key in `view` is out of scope.

## Why

On 2026-11-03 the human asked to pause the herd once in-flight work landed.
With no pause, the shepherd prompted the lead in prose; the instruction
survived the lead's handoff only because the lead copied it into its
handoff file, and a relay landed in the lead's reviewer subagent instead
(LH-100). A file in the state directory survives handoffs, restarts and
`revive` without anyone remembering it, and `feed` and the watch honour it
for leads and the shepherd alike.

Rejected:

- **Freeze now** (interrupt every member): interrupting a turn loses its
  work, and handoff plus restart already covers clearing members out.
- **A field in the herd file**: pausing is runtime state, not configuration,
  and a command rewriting the TOML would lose the human's comments.
- **A ledger field**: the ledger records members, not herds.
- **One global pause flag for `--all`**: two kinds of state to reason about,
  and `resume <herd>` couldn't lift one herd out of it.
- **Prompting the lead on pause and resume**: the pause would again rest on
  the lead remembering a prompt; `feed` and the watch enforce it instead.
