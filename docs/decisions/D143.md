# D143

## Decision

Every herd gets an attended grill template, so a shepherd starts a grill as
a member (D112) instead of grilling in its own pane. Grilled with the human
on LH-474 (2026-11-23); amends D112, whose grills ran only where a herd file
was hand-built for them.

- **Always written.** `loopherd init` writes `[template.grill]` (`attended =
  true`) for every herd, with no question and no flag; the D37 summary lists
  it as `grill (attended)`. A human who doesn't want it deletes it.
- **Prompt beside the herd file.** The prompt is `<herd>-grill.md` in the
  herds directory, named by `prompt_file`, and is written, refused when it
  exists, rolled back and shown by `init --diff` as `<herd>-lead.md` is. It
  is filled per tracker like the issue template.
- **Template shape**, per tracker, mirroring the issue template without
  `type` and `skill`:

  | Tracker | params | name | branch | done / merged |
  |---|---|---|---|---|
  | GitHub | `number, slug` | `{herd}-grill-{number}` | `docs/{number}-{slug}` | the issue template's |
  | local | `id, slug, path` | `{herd}-grill-{id}` | `docs/{id}-{slug}` | the issue template's (`merged` only with GitHub) |
  | other | `number, slug` | `{herd}-grill-{number}` | `docs/{number}-{slug}` | `(fill in)` done, as the issue template |

- **What the prompt says.** Invoke the `grilling` skill, with a fallback of
  a few lines for when it isn't installed (one question at a time, each with
  a recommended answer, facts looked up by the grill). D132's interactive
  and in-pane batch modes. Record the decision where the repo's AGENTS.md
  or docs say decisions go, else `docs/adr/<NNNN>-<slug>.md`, in a PR that
  closes the issue. Show each implementation issue before filing it. When
  done, tell the human and run `herdr agent focus {shepherd_pane}`; no
  close-out after the merge, since the PR closes the issue and the herd's
  `merged`, `after_merge` and `done` reap the grill.
- **Existing herds.** `loopherd init --grill` adds only the template and
  its prompt file to an existing herd, refusing when a `grill` template or
  the file already exists. The skill offers it when a grill is asked for and
  `loopherd herds` shows no attended template. Neither `herds` nor doctor
  flags its absence.
- **Batch stays opt-in.** Init doesn't scaffold D132's unattended
  `grill-batch`; the attended prompt's in-pane batch mode covers asking for
  picks.
- **Grill or wayfinding.** The skill routes a request, and the grill prompt
  carries the mid-grill signal:
  - **Grill**: one decision settles it; a handful of questions answerable
    with the human in one sitting, ending in one decision and a few
    implementation cards.
  - **Wayfinding**: several decisions that depend on each other, some
    needing research or a prototype first, likely spanning sessions, or a
    destination not yet clear.
  - **Signal mid-grill**: a grill that keeps finding questions it can't
    settle without research, or keeps filing grilling cards rather than
    implementation cards, has outgrown itself; it stops and suggests
    `/wayfinder` (mattpocock-skills).

  `/wayfinder` is human-invoked, so the shepherd only suggests it, says
  why, and lets the human pick; it doesn't start a grill meanwhile.

Built as LH-497 (init writes the template and prompt), LH-498 (`init --grill`,
after LH-497) and LH-499 (the skill, after LH-498).

## Why

A new user's shepherd ran all her grillings in its own pane because her
herd had no grill template; `loopherd init` wrote only `[template.issue]`,
and this repo's own herd lacked one until LH-474 started.

- **Always, not asked.** An attended template is inert until `add`: never
  in `[queue] templates`, no slot. A question would lengthen the first run
  LH-466 wants Enter-through, and a flag would guard nothing.
- **A file, not inline.** The prompt is long prose like the lead's, and
  init already writes, refuses and rolls back a file beside the herd.
- **Fallback over a doctor check.** The installer only offers the plugin;
  a fallback makes the grill work either way, where a check would nag
  everyone who declined it.
- **`init --grill` over a `herds` note.** The offer comes when a grill is
  asked for, and gives an old herd the same prompt a new one gets; a
  standing note would nag a herd that removed the template on purpose.
- **Batch opt-in.** An unattended batch grill needs a routed source, a
  label and a stop protocol per tracker, which pays off only for a led herd
  with a stream of grilling cards.
- **A PR, the repo's convention first.** D112's close-out is built on a
  merged PR; deferring to the repo's documented home for decisions means a
  repo like this one (D-files) needs no prompt edits, and `docs/adr/`
  matches the plugin's `domain-modeling` skill.
- **No close-out in the grill.** The tracker closes the issue on merge and
  the herd reaps the grill; the poll-and-ping in this repo's prompt exists
  only because Trello closes nothing by itself.
- **Fixed `docs/` branch.** A grill's output is always a decision doc; one
  param fewer is one fewer for the shepherd to get wrong.
