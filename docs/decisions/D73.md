# D73

## Decision

The herdr plugin hooks `pane.moved` to `loopherd herdr-event-hook`. On a
move within a workspace, where `data.pane.pane_id` equals
`data.previous_pane_id`, the hook sets the `tab_id` of the non-retired
member on `HERDR_SOCKET_PATH` in that pane to `data.pane.tab_id`, under the
ledger lock. It skips the update unless the entry still holds that pane and
`data.previous_tab_id` (or no tab), so an event that arrives late, for a tab
the member already left, changes nothing. A move to another workspace, an
event missing any of these fields, or one naming no member changes nothing.
The hook still never calls herdr. Closing the member's old tab then records
no `gone`, and closing its new one does (D69).

The [payload](../research/herdr-events.md#panemoved) was probed on the dev
herdr over a raw socket subscription, without linking the plugin (D62).

Limits:

- A move to another workspace gives the pane a new id, but the agent keeps
  the old one in `HERDR_PANE_ID`. Its report, its Stop and SessionStart
  hooks and a lead's PreToolUse gates all look it up by that old id, so the
  hook leaves the entry alone. Closing the old tab or workspace records a
  false `gone`, and closing the new one records none. Own-pane lookups
  across workspaces are LH-265.
- Moving a member's pane out of a tab it was alone in fires `pane.moved`,
  then `tab.closed` for the tab it left. herdr runs hooks unordered (D66),
  so when the close's hook reads the ledger before the move's hook writes
  it, the member gets a false `gone`. Every member starts alone in its own
  tab, so this is the usual move. LH-266 tracks it.
- Two moves whose hooks run in reverse order leave the entry on the first
  move's tab: the second is skipped as from a tab the member had not yet
  reached.
- A failed or dropped hook leaves the old tab recorded; no watch poll
  corrects it.

LH-257 settled it, with the human's choice to follow same-workspace moves
only.

## Why

`herdr pane move` within a workspace changes a pane's tab while the agent
keeps running. Following the move from the event's own payload keeps the
recorded tab, which `tab.closed` looks members up by, true without a herdr
call in a hook that must stay fast and offline. Following a move to another
workspace would mean rewriting the pane id that the agent's own hooks and
gates match on, so it waits for LH-265.
