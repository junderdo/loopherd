# D56

## Decision

A local-tracker herd in a repo whose origin is GitHub can be written without
GitHub, two ways:

- On a terminal, with the tracker local, the GitHub `owner/name` question
  names origin's repo and takes Enter for none. Typing the slug keeps GitHub.
- `--no-github` does the same for a scripted run. It goes only with a local
  tracker, and clap refuses it alongside `--repo` or `--gh-account`.

Either gives the same herd as a non-GitHub origin: init makes no gh call,
the herd has no `merged` check, workers push a branch and open no PR, and
init warns that `after_merge` never runs. Off a terminal without the flag, a
GitHub origin still keeps its PR `merged` check, and on a terminal
`--gh-account` keeps origin's repo as the default.

`init --diff` reads the choice back (D38): a local-tracker herd file with no
`merged` key diffs without GitHub, needing no `--no-github`.

This amends D40, where a GitHub origin always meant the PR `merged` check.
`loopherd release` still asks GitHub for an open PR whenever origin is GitHub,
whatever the herd records.

LH-169 built it.

## Why

Before this, init offered "Enter for none" only when origin wasn't GitHub, so
a human with no working `gh` login, or who doesn't want PRs, couldn't init a
local-tracker herd in a GitHub-hosted repo. The human chose both forms: the
terminal question for interactive runs, the flag for scripts. Keeping GitHub
the scripted default leaves existing scripted inits unchanged.
