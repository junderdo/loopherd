# D97

## Decision

Amends D89's "Writes allowed" and its "state dir" gap (LH-298). A lead's
sandbox no longer allows the whole state dir; only the parts the lead
writes from inside it.

- **Writes allowed in the state dir**: `reports/`, `handoffs/` and the
  lead's own `broker/<lead>/requests/` (D98), never another lead's, whose
  broker would take its requests as that lead's. `lead` and `revive` make
  all three before the lead starts; the file tools are denied `broker/`.
  - From inside its sandbox a lead writes:
    - its own mailbox (`report`);
    - its handoff (`handoffs/<lead>.md`, with its own tools);
    - its watch's files: `reports/watch-<lead>.lock`, `.fired` and
      `<lead>.merges` with its `.merges.lock`, its workers' mark files and mailboxes, and the shared
      cursors `reports/.cursor` and `.watch-cursor`;
    - pane labels.
  - Hooks run outside the sandbox.
- **Read-only to the lead's Bash**: the rest of the state dir.
  - That includes `paused/`, `shepherd.json` and `ledger.json` with their
    locks, `restarts/`, `handoff-asked/` and the top-level locks.
  - The file tools see no sandbox, so `paused/`, `shepherd.json`,
    `ledger.json` and their locks are also `Edit` deny rules.
- **The shepherd's watch files** are each a `denyWrite` entry and an
  `Edit` rule: `reports/watch.lock` and `reports/watch.fired`. They are
  created empty if missing, and left as they are otherwise.
- **`restart` and `prompt` run outside the sandbox**, as `feed` does.
  - Both write the ledger, and a lead restarts its own members after their
    handoffs.
  - Each refuses, for a calling lead, any entry outside its own herd.
  - `loopherd restart *` covers `restart --self`.
  - A form the exclusion misses, such as `cd x && loopherd prompt y`,
    runs inside the sandbox. There the lead's Claude is out of sight of
    the parent-pid walk (D58), so the herd check can't run. Both refuse,
    before anything reaches herdr, a run that can't open the ledger lock
    for writing.
- **`revive` refuses a calling lead**, except on `--dry-run`. Inside the
  sandbox it would start Claudes before failing on the ledger. It always
  runs there for a lead, so it refuses on the same read-only ledger
  lock. `lead` fails on the config dir as before. Both belong to the
  shepherd or the human.
- **A lead's watch run as the shepherd's** (a pane on another herdr)
  now fails on the shepherd's watch lock.

## Why

- **A deny on one file doesn't outlast a rename.** On Linux the sandbox
  enforces a denied file inside an allowed directory by bind-mounting
  over that file. When a process outside renames a new file over the
  path, as every ledger save and `shepherd.json` write does, the mount
  comes off inside the running sandbox. A command the lead left running
  can then write the real file.
  - Tried with bubblewrap: a file deny fell to a rename from outside.
  - The same rename inside a directory the sandbox doesn't allow stayed
    refused.
  - The live test checks both against a real sandboxed lead.
  - So the human's and the shepherd's files are protected by their
    directory, not by name.
- **The shepherd's watch files are only written in place**, never renamed
  over or deleted, so a file deny holds for them inside `reports/`. They
  exist before the lead starts: on Linux the sandbox holds a missing
  denied path with a placeholder file, which would sit in the way of the
  first real write.
- **A read-only ledger closes D89's forged-entry gap.** A lead can no
  longer write a worker entry, its own session included, for `revive` to
  resume unsandboxed. The `unsandboxed` flag is no longer the lead's to
  clear.

## Still open

These stay writable to a lead, through `reports/` and `handoffs/`:

- other agents' mailboxes and handoffs, the shepherd's included;
- the shared cursors;
- other agents' mark files.

None has a fixed name, and a lead's own files sit beside them. A lead's
file tools may still write the state dir's other top-level paths, such as
`feed.lock` or `restarts/`. LH-307 holds the design: run `report` and
`watch` outside the sandbox, and move a lead's handoff into a directory
of its own.
