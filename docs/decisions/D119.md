# D119

Amends D108.

## Decision

- A broker also records a `file <dev> <ino>` line: the device and inode of
  the executable it runs, read through `/proc/self/exe` (its path where
  there is no `/proc`). A lock without one is from before this decision and
  reads as unrecorded.
- `loopherd doctor` compares each running broker with the `loopherd` on
  PATH, canonicalized, falling back to its own executable when there is
  none. A broker runs that binary when the recorded dev/ino match the
  file's; the version is shown but no longer compared.
- The fix doctor names is `the shepherd runs loopherd broker-restart
  <lead>`.
- `loopherd broker-restart` resolves its executable first, before it waits
  for the old broker to drain, and starts the new broker from that path
  (`loopherd` on PATH if a reinstall already replaced it).

## Why

The version string can't tell two dirty builds of one commit apart, nor two
builds without git; the file's identity changes with every rebuild and
reinstall. Brokers are started by `broker-restart` and `revive` from the
installed binary, so a doctor run from `target/release` should judge them
against the install, not itself. A lead whose `[lead]` sets `install = true`
sees doctor's output from `scripts/install` but is refused `broker-restart`,
so the fix names who runs it. A reinstall during the up-to-4h drain renames
over the binary, and `/proc/self/exe` then reads `<path> (deleted)`, which
can't be spawned.
