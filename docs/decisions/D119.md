# D119

## Decision

Amends D97 and D107 (LH-339). Each agent's mailbox lives in a directory of
its own: `reports/<name>/mailbox.jsonl`, for workers, leads and the
shepherd alike.

- **Writes go only there.** `report`, the hooks, `watch`'s notes, `retire`'s
  usage line, `revive` and the broker all append through one function, which
  makes the directory.
- **Readers read the flat file first.** A `reports/<name>.jsonl` an older
  release wrote is read as the start of the mailbox, then the new file.
  The flat file no longer grows, so the read cursors' byte offsets into it
  stay valid across the upgrade, and nothing is moved or rewritten. A torn
  last line in the flat file is ended before the new file is read, so it
  can't swallow the first new report.
- **Listing** counts a `<name>.jsonl` file and a `<name>/` directory holding
  `mailbox.jsonl` as the same agent's mailbox.
- **`herd remove`** deletes both files and then the agent's mailbox
  directory once it is empty.
- **Unchanged**: marks, cursors and watch locks stay in `reports/` beside the
  directories, and a lead's sandbox still denies all of `reports/`; its broker
  writes its mailbox. Allowing a worker its own directory is the worker
  sandbox's card.

## Why

- **Directories, not names** (D97, D107): a per-file deny inside an allowed
  directory falls to a rename from outside the sandbox, so a sandbox that is
  to allow one agent's mailbox without the others needs it in a directory
  of its own, the same move LH-307 made for handoffs.
- **Read both, not newest-wins.** A handoff is one document, so LH-307's
  `find` picks the newer file; a mailbox is a log whose history `stats`,
  `retire` and the watch's stop judgment all read, so the flat file is its
  prefix rather than a rival.
- **No migration by rename.** A sandboxed writer can't rename across
  `reports/`, and moving the file under a reader would leave its cursor
  pointing into a file it no longer reads.

## Limits

- An older loopherd still running after the upgrade appends to the flat
  file; those lines are read, but out of order with the new file's.
- The flat-file fallback stays until a later release removes it.
