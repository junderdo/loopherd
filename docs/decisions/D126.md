# D126

Amends D26 and D62.

## Decision

`scripts/install` offers loopherd's herdr plugin as a third extra, after the
agent types and the mattpocock-skills plugin, default no (LH-420).

- **When it asks.** Only on a terminal, with `herdr` on `PATH`, and when
  `herdr plugin list --plugin loopherd --json` shows the plugin missing or
  older than the `version` in this checkout's `herdr-plugin/herdr-plugin.toml`.
  Otherwise it prints which case applies: no terminal, no herdr, herdr
  couldn't list, already at this version, linked (left as is), or newer than
  this checkout (left as is).
- **What a yes runs.** `herdr plugin install junderdo/loopherd/herdr-plugin`,
  or `herdr plugin update loopherd` over an older install that isn't linked.
  Both fetch from GitHub (update at the ref herdr recorded), not from this
  checkout, so the update question names both versions rather than promise
  the checkout's. On a terminal herdr still shows its own preview and
  confirmation; `--with-herdr-plugin` passes `--yes`, since it asks nothing.
  herdr's output is printed as is; a failure is reported on stderr and the
  install goes on, unlike a failed skills install. The plugin list gets 10
  seconds where `timeout` exists, so a wedged server can't hang the install.
- **Flags.** `--with-herdr-plugin` installs or updates it asking nothing
  else and, like the other extras, means just the extras named.
  `--no-extras` skips it and refuses beside it. `--remove` skips it.
- **`--settings` runs never touch herdr.** herdr plugins are global to the
  user, so a run with `--settings` (tests, manual runs) skips the plugin
  with a line saying so, even with `--with-herdr-plugin`.

## Why

The README asked the human to run `herdr plugin install` by hand and
`loopherd doctor` only warned afterwards. `herdr plugin install` registers the
plugin without writing the human's herdr `config.toml`, so offering it keeps
loopherd out of that file; key bindings stay a manual step. (Amended by
D129: a separate opt-in extra writes them.) A plugin
failure isn't worth failing an install whose binary and hooks are already
in place, and doctor still reports the plugin's state last.

The check compares versions only, so plugin changes made without a version
bump aren't offered; LH-420 asked for the version check.
