# D126

## Decision

A sandboxed worker in a `merge_guard = "credentials"` herd gets its herd's
split credentials, as D107 and D114 decided (LH-342). Amends D95 and D107.

- **One confinement for leads and workers.** `sandbox::confine_credentials`
  writes D114's set into a member's settings: `credentials::confined`'s `env`
  (the herd's token as `GH_TOKEN`, empty `SSH_AUTH_SOCK` and inherited GitHub
  token variables, `GIT_CONFIG_*` clearing `credential.helper` and rewriting
  origin to `loopherd-<herd>`), its `denyRead` ahead of the member's own, each
  also a `Read(…)` deny for the file tools, and its `allowRead`. A lead adds
  its broker's directory (D121); a worker adds nothing.
- **Refused under `require` and `prefer` alike,** as `NotStarted`, so a feed
  goes on with its other tasks: a worker whose herd lacks its key or token,
  whose herd sets `[worker] unix_sockets = "all"`, or whose sandbox can't
  start (the probe, sockets it can't block, or no worktree of its own). The
  fix names `[lead] merge_guard = "hook"`, with `[worker] sandbox =
  "prefer"` under `require`, since `prefer` alone no longer starts it.
  `restart` refuses such a worker running unsandboxed the same way.
- **An invalid herd.** A credentials herd whose `[worker]` turns the sandbox
  on with `unix_sockets = "all"` is invalid, as D114 made the `[lead]` pair:
  `loopherd herds` names it and doctor fails on it. With `[worker] sandbox =
  "off"` the switch opens nothing, so the herd stays valid.
- **Doctor** warns for a credentials herd whose `[worker] sandbox` is `off`
  (or unset), and no longer for `prefer` there, which can't start a worker
  unsandboxed. `lead` and `revive` warn that the lead's workers hold the
  human's gh only while that switch is `off`. LH-360 makes `require`
  mandatory.
- **init** writes `GH_TOKEN=${GH_TOKEN:-$(gh auth token --user <account>)}`
  in a credentials herd's worker prompts (every gh line and the push) and
  `done`/`merged` checks. Both are templates, so the braces are written
  doubled (`${{GH_TOKEN:-…}}`); the queue's `source` and `backlog` aren't and
  keep them single. Before this, init wrote the checks' braces single, and
  `loopherd herds` called every credentials herd it made invalid.

- **Upgrading.** A worker started before this, or before its herd turned to
  credentials, keeps the settings it was started with, and `restart` checks
  only that it got some: quit its Claude and `loopherd revive --name <worker>`
  to resume it confined. A herd file from an older `init` prompts
  `GH_TOKEN=$(gh auth token …)`, which fails in the confined sandbox; run
  `loopherd init --diff` and take the new lines.

## Why

- **The split already fits workers** (D107): they push feature branches and
  open PRs, which the deploy key and token allow, and can't merge, which the
  token and rulesets refuse. A fake `gh` and `ssh` test runs the init-written
  lines under a worker's settings `env`: the push reaches
  `git@loopherd-<herd>`, `gh pr create` runs on the herd's token, and
  `gh pr merge` fails on it while the human's own gh would merge.
- **`prefer` can't mean unsandboxed here.** An unsandboxed worker holds the
  human's gh, which undoes the lead's guard (D114), so a credentials herd
  refuses rather than warns.
- **One function, not two copies,** so a gap closed for leads closes for
  workers too.
