# D108

## Decision

A broker records the binary it runs, and doctor warns when that isn't the
binary doctor runs (LH-312).

- On taking its lock, a broker appends `version <loopherd --version>` and
  `binary <its executable's path>` lines to `<config dir>/broker/<lead>.lock`,
  after D98's timeout and start-mark lines.
- `loopherd doctor` warns, for each running broker of a lead it checks, when
  the recorded version or path differs from its own, or when the lock records
  none (a broker from before this decision). The fix it names is
  `loopherd broker-restart <lead>` (D106's command, not `revive`, which
  leaves a running broker alone). `scripts/install` shows it, since it runs
  doctor last.
- A lead's client that gets a reply it can't parse says the broker may run
  an older loopherd and names `broker-restart`, beside the existing
  `predates this loopherd` error for a broker that can't read a request.

## Why

A merge that changes the broker's request or reply format leaves running
brokers on the old binary, and nothing said so until a lead's command failed.
The version string names the commit off a release tag, so a rebuild from a
new commit differs; the path catches a broker started from another build.
Restarting brokers automatically stays out of scope.
