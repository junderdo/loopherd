# D92

## Decision

`loopherd stats` adds tokens per task, each run's outcome, and comparison
across windows and templates. Amends D30, which read only the ledger and
mailboxes and left leads out. Rounds stay D30's count of `done` reports.

- **Tokens per task.** A worker's tokens sum every assistant message in
  every Claude session its mailbox's `stop` entries name (so handoffs and
  restarts add up) and in each session's `subagents/` transcripts, counting
  each message id once, since a transcript repeats a message's usage. Kept
  per model as input, cache write, cache read and output.
- **Recorded at retire.** Transcripts are deleted after Claude's
  `cleanupPeriodDays` (30 by default), so retiring a worker writes its
  totals to its mailbox as a `usage` entry. Stats reads that entry; for an
  open worker, or a retired one without it, it reads the transcripts while
  they exist, else shows `-`, left out of the medians like D30's.
- **Shown.** The table gets `in` (input + cache write + cache read) and
  `out` columns, and the herd summary their medians; `--json` gives the
  per-model four-way split.
- **Lead overhead.** Each herd gets one line with its lead's tokens over the
  window, subagents included, summed the same way and not split across
  tasks. The lead still gets no row.
- **Details settled in LH-294.** A worker's sessions are those its `stop`
  entries name within its own run (from `created` to `retired_at`), so a
  reused name's earlier run doesn't count. Retire writes no `usage` entry
  when none of those transcripts is left, so the row shows `-` rather than
  zero. A transcript that is gone while others remain is skipped and the
  rest summed. The lead's window is applied per message, by its
  `timestamp`, across every session its mailbox names, so it counts only
  transcripts still on disk; leads get no `usage` entry. A run's sessions
  include the ledger's current one, which a first turn has before any
  `stop`. Open workers get `in` and `out` too, read from the transcripts.
  A rerun of `retire --close` records a `usage` entry a failed first try
  left out, stamped at the retirement, and never a second one.
- **Outcome**, recorded when the worker retires: `merged` when feed's
  `done` check retires it with its template's `merged` check passing,
  `closed` when feed retires it without that, `released` by `loopherd
  release`, `retired` for a plain `loopherd retire`. Workers retired before
  this show `-`. A new column shows it; the medians cover only `merged`
  runs, and the summary counts the others apart.
- **Comparing.** `--until` beside `--since` (same forms; keeps members
  started before it), and the summary is given per template within each
  herd as well as for the herd.
- **Details settled in LH-296.** `--until` is exclusive where `--since` is
  inclusive, so two windows that share a bound count no member twice. An
  `--until` at or before `--since` is refused as a usage error, since it
  can keep nothing. The window bounds the lead's messages at both ends too.
  A template's summary covers its retired runs, as the herd's does; a
  herd with one template still gets the template line, and `--json` gives
  them as `templates`, each a `template` and a `summary`, by template name.

Left out: dollars (prices change, and a subscription isn't billed per
token; an optional `[stats.prices]` table can come later); splitting the
lead's review cost across tasks; the shepherd's own spend; a finer round
count than `done` reports; runs whose transcripts are past cleanup with no
`usage` entry.

## Why

Grilled on LH-240 (2026-11-19). Template and prompt changes should be judged
by numbers, and D30 already gives rounds and times, so cost and outcomes
were the gap.

- **Rounds as `done` reports** stay: a `done` for a base merge adds a round
  without a review, but that noise falls on every template alike. A
  `--round` report field relies on members, and PR comments tie stats to
  GitHub.
- **Tokens, not dollars**: the transcript records tokens reliably; a price
  table ages with every price change.
- **`in` and `out` columns**: summed, cache reads dwarf the rest; output is
  what the model produced and input what each turn re-read.
- **Lead overhead per herd**, not per task: no reliable link ties a lead's
  subagent to a PR, and a per-herd total still shows whether a change made
  review cheaper.
- **Medians over merged runs only**: a parked five-round PR would skew the
  work that landed; its own row still shows its cost.
- **`--until` and per-template summaries**: the usual question is whether a
  prompt change helped, which two windows split by template answer;
  `--json` serves anything finer.
