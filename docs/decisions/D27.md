# D27

## Decision

`scripts/install` reads the mattpocock-skills plugin's skill names, for the
overlap listing D26 asks for, from the plugin's own
`.claude-plugin/plugin.json` on GitHub: at the commit the
`claude-plugins-official` catalog pins when that marketplace is added, else
at the repo's `HEAD`. When it can't read them it says so and still offers the
plugin.

Naming an extra (`--with-agents`, `--with-skills`, or both) installs just
those and asks nothing about the other; with neither, a terminal run asks
about each. `--no-extras` with either is an error.

With `--settings <file>`, the `claude` calls run with `CLAUDE_CONFIG_DIR`
set to that file's directory, so the plugin lands beside the hooks and agent
types rather than in the human's own Claude config.

## Why

`claude plugin details` lists a plugin's skills only once it is installed,
and the overlap has to be shown before asking. The catalog's pinned commit is
what `claude plugin install` fetches, so its manifest names the skills that
will load; a list kept in this repo would drift from the plugin.

A flag that names one extra reads as the whole request, which keeps scripted
runs from stopping on a question about the other.

`claude plugin install` takes a scope, not a settings path, so pointing
`CLAUDE_CONFIG_DIR` is the one way to keep a `--settings` run, such as a test
or manual run against a temp file, off the real config.
