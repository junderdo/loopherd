# D111

## Decision

Amends D97, D98, D102 and D110's `report` row (LH-307). A lead's sandbox writes, in the state
dir, only its own handoff directory and its own broker's `requests/`.

- **Handoffs, one directory per agent.** Every agent, the shepherd
  included, writes `handoffs/<name>/handoff.md`; once read it moves to
  `prev.md` beside it.
  - The Stop hook's ask, `restart`, `restart --self`, the shepherd's
    SessionStart resume and `herd remove` all use the new place.
  - Readers fall back to the flat `handoffs/<name>.md` an older release
    wrote, and move it into the new directory's `prev.md` once used. New
    handoffs are written only to the new place. A later release drops
    the fallback.
  - `shepherd` stays a reserved name.
- **A lead's report goes through its broker**, as a `report` request the
  broker writes to the lead's own mailbox; a question also labels its
  pane there, replacing the separate label request. With no broker
  running, the report fails like the lead's other routed commands. A
  broker too old to read the request gets the report written by the lead
  itself, with a warning that a question's pane gets no label, which
  works while the lead still runs on the settings it started with (D125).
- **The lead's `allowWrite` in the state dir** is `handoffs/<lead>/` and
  `broker/<lead>/requests/`, nothing else. `reports/` leaves it, and with
  it the shepherd's watch-file denies, which only guarded files inside an
  allowed `reports/`.
- **The file tools** are denied `reports/` whole, and, as D102 does for
  `broker/`:
  - on Linux, `Edit(//<state>/handoffs/*)`, a glob the Linux sandbox
    reads as a literal `*`, so Bash keeps its own directory while the
    file tools are refused all of `handoffs/`, the lead's own directory
    and directories made later included;
  - elsewhere, a literal deny on the shepherd's flat `handoffs/shepherd.md`,
    missing or not;
  - elsewhere, also a literal deny on each entry of `handoffs/` but the
    lead's own, as they stand when its settings are written. On Linux
    none is named: Bash can't write `handoffs/` outside its own
    directory anyway, and a named path that later goes missing, as a flat
    handoff does once used, would get the sandbox's empty placeholder,
    which a reader would take for a handoff.
- **`loopherd handoff` writes the calling member's handoff from stdin**
  into its own directory. A lead must use it: Claude Code checks a Bash
  redirect's target, and `cat`, `tee` and `sed`, against the same `Edit`
  denies, so on Linux those are refused the lead's own directory too. The
  Stop hook's ask tells a lead so.
- **`lead`, `revive` and `restart` make `handoffs/<lead>/`**, the
  shepherd's and every herd's lead's handoff directory before the lead's
  Claude starts or is cleared, so off Linux a literal deny names them. No literal
  deny covers the lead's own directory.

## Why

- **Separation by directory, not by name.** A deny on one file inside an
  allowed directory doesn't outlast a rename from outside the sandbox
  (D97). With each agent's handoff in a directory of its own, the
  sandbox allows just the lead's.
- **The shepherd follows its handoff unsandboxed.** Before this, a lead
  could write `handoffs/shepherd.md`, which the shepherd's resume reads
  and acts on. The flat fallback keeps that path readable for an
  upgrade, so the file tools' glob refuses planting a new flat file too.
- **`reports/` needed nothing from inside the sandbox any more.** The
  lead's watch runs outside it (D104), and its report now runs in its
  broker. D98 kept the report in the lead because a single-threaded
  broker could leave it waiting behind a long feed; the broker now
  answers quick requests while a feed runs (LH-311).
- **The glob costs the lead its file tools and Bash redirects on its own
  handoff.** No glob can mean "every name but this one" (D102), and a
  literal deny alone misses directories made after the lead's settings
  were written, such as a later worker's, and a flat shepherd handoff
  planted where none was. loopherd's own binary writes the file, which
  Claude Code doesn't analyze, as `broker/*` already relies on for
  requests. On Linux a literal deny on a missing path would leave the
  sandbox's empty placeholder there, which the shepherd's fallback would
  read as a handoff, so that deny is only for the other platforms.
- **The live sandboxed-lead test checks it.** From inside a real lead's
  sandbox, Bash is refused its own mailbox, another agent's mailbox, the
  shepherd's handoff in both layouts and another agent's handoff
  directory, and writes its own handoff; a redirect into its own
  directory is refused and `loopherd handoff` writes it; the Write tool
  is refused a flat shepherd handoff, a mailbox and a handoff directory
  made after the lead started; its report and `restart --self` go
  through its broker. The live watch test shows the bare watch writing its lock in
  `reports/` from outside the sandbox.

## Still open

- **macOS** applies globs, so there the lead's file tools get only the
  literal denies and may write a handoff directory made after the lead's
  settings were written, until its Claude starts again. Its Bash still
  can't. Not run on macOS.
- A lead running `loopherd watch` in a form that keeps it inside the
  sandbox (D104) now fails at once on `reports/`, rather than blocking
  `git config` writes. A lead's plain `loopherd reports` fails too, since
  it saves the read cursor there; `--all` works.
- **Upgrading.** For each running lead, in order: `loopherd
  broker-restart <lead>` (D106; unneeded once its broker moved by itself,
  D124), quit the lead's Claude, then `loopherd revive --name <lead>`
  (D125). Until its broker restarts, its `restart --self` looks for the
  flat handoff. Until it is revived, its settings still allow `reports/`;
  `restart` and `revive` warn that its sandbox predates its herd's
  switches, which here means predates this release.
- Lock files a lead can still `flock` read-only are LH-313's.
