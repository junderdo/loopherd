# D137

## Decision

A session's context window comes from its model (LH-465), so most users
never set `context_window`.

- **Source.** The Stop hook and the shepherd's watch read the `message.model`
  of the transcript's last main-thread assistant turn with usage (the turn
  they already measure) and look it up in a built-in table: Opus, Sonnet,
  Haiku and Fable 4.7 and later have 1M; older ones (Haiku 4.5, Opus 4.6)
  have 200K.
- **Order.** `context_window` in config.toml wins, as an override for
  unusual setups; then the model's window; then 200K when the transcript
  has no turn yet or the model isn't in the table.
- **Percentages.** A limit written as a percentage (D136) resolves against
  the same window, then takes the 10000-token floor and the 80% cap.
- **Unknown model.** Falls back to 200K and leaves one `note` per session
  naming the model and `loopherd config set context_window <tokens>`.
- **Setup.** `loopherd setup` asks for `context_window` only when it is
  already set; `setup --context window=<n>` and `config set` still set it.
  With no window set, `setup` and `init` check a limit against 80% of the
  largest known window (1M), since each session's model caps it again.
- **Doctor.** Each stop records its window and source; `doctor --verbose`
  shows the last one for every open member.

## Why

New users don't know their model's window, and a 200K default capped 1M
sessions at 160K. Claude Code's hooks don't carry the window or the model;
only its status line input has `context_window.context_window_size`, which
loopherd doesn't run. The Models API reports `max_input_tokens` but needs an
API key many Claude Code users don't have. Opus 4.6 has 1M only when picked
as `[1m]`, which the transcript's model id doesn't show, so it takes the
safe 200K.
