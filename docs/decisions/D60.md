# D60

## Decision

A herd can say it is running low on ready work while its backlog holds
unready tasks. A lead then triages those tasks for the human.

- **Unready tasks.** An optional `[queue] backlog = "<cmd>"` prints every
  open task that isn't claimable, one per line (key, then title). It leaves
  out blocked tasks and keeps ones waiting on the human (`need-human`).
  Unready is its line count. Claimable is feed's own `claimable()` count, so
  a task skipped because a parked member holds its name counts as neither.
  `source` keeps its contract.
- **Counts.** `loopherd status` and `status --json` show each herd's
  claimable and unready counts, led or not.
- **The line.** Only a lead's watch prints `<herd> running low  <n>
  claimable, <m> unready`, when claimable is at or below `max` and unready
  is above 0. It prints once per streak; the streak ends when claimable
  rises above `max` or unready reaches 0. A paused herd prints nothing and
  keeps its streak. No `[notify]` kind is added. Amended by D80: a herd
  with 0 claimable and no open worker gets a `no workers open` line on a
  streak of its own, even mid-way through this one.
- **Triage.** On the line, the lead has a read-only subagent sort the
  unready tasks into ready, needs a decision (naming it), needs spec
  (saying what's missing) and stale (saying why), and reports the result as
  a `question`. The shepherd relays it. Once the human approves, the
  shepherd labels the ready tasks, archives the stale ones the human
  confirms, and comments what's missing on each needs-spec task. Only the
  shepherd, with the human's approval, marks a task ready; no lead switch
  covers it.
- **Unled herds** get no line; the skill tells the shepherd to triage when
  `status` shows the herd low.
- **`loopherd init`** fills `backlog` for GitHub and local markdown by the
  same rule, and marks it `(fill in)` for other trackers.

Out of scope: warning about dependency chains, a blocked count, a
`loopherd triage` command, and running herd checks in the shepherd's watch.

LH-228 settled it.

## Why

`source` prints only claimable tasks, so nothing could tell an empty backlog
from one full of tasks nobody marked ready. The loopherd-cards herd ran one
member for a while with ten unlabelled cards waiting, six of them ready.

A separate command keeps every existing herd file valid, and its lines are
the triage's input. Blocked tasks are left out because triage can't make
them ready; `after_merge` unblocks them. Tasks waiting on the human are kept
because those are the ones forgotten while a queue runs dry. Only a lead's
watch runs a herd's checks, so only it prints the line; the counts in
`status` cover unled herds without making the shepherd's watch run checks.
A threshold of `max` fires while a slot can still be filled, rather than
after one sits empty. One line per streak means a declined triage isn't
repeated. The lead's `question` already notifies, so a `low` kind would
send twice. Marking a task ready is a judgment of scope, so it stays with
the human, and the shepherd only applies what the human approved.
