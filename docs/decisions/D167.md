# D167

Amends D122.

## Decision

A release update asks none of a fresh install's questions, as
`scripts/install --update` doesn't (LH-501).

- **`LOOPHERD_UPDATE=1`.** `loopherd update` runs the target release's
  `install.sh` with `LOOPHERD_UPDATE=1` in its environment, beside
  `LOOPHERD_VERSION` and `LOOPHERD_NO_SPLASH=1`.
- **What install.sh does with it.** No splash and no offers, terminal or
  not: it refreshes the agent types `agents.sha256` says loopherd
  installed (an edited one asked about on a terminal, else kept with a
  warning), prints the `claude plugin update` line when the
  mattpocock-skills plugin is installed, and leaves the herdr plugin and
  its key bindings alone, which D122's doctor line covers. Plain `setup`
  still runs, asking only for groups still unset.
- **Not a human's switch.** `install.sh` documents it only as what
  `loopherd update` sets; D154's no-options rule stands.

## Why

`install.sh` takes no options (D154), and an older release's copy, which
`--version` can install, refuses any argument, so a flag would break moving
to it. An environment variable is ignored there instead: the update still
works, only asking again, and `LOOPHERD_NO_SPLASH=1` keeps that older one's
splash off. `--no-extras` doesn't exist in `install.sh` and in
`scripts/install` skips setup, which an update still wants for groups added
since. Sharing `install-extras`' `update` modes with `scripts/install
--update` keeps the two update paths refreshing the same things.
