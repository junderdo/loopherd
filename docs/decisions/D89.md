# D89

## Decision

Each lead's Claude runs in the Claude Code sandbox, as D83 decided, from a
settings file loopherd writes for it (LH-280).

- **The file.** `<config dir>/sandbox/<lead>.json`, passed as `claude
  --settings <file>`.
  - `lead` writes the file before starting the lead.
  - `revive` rewrites it from the herd's current switches and swaps the
    lead's recorded `--settings` for the fresh one. Members' args are
    resumed as recorded.
  - `restart` sends `/clear` to the running Claude, so it writes nothing.
    It checks that the lead's recorded args hold `--settings <its file>`.
- **What it sets.**
  - Sandbox: `enabled`, `failIfUnavailable`, `allowUnsandboxedCommands: false`.
  - Network: `allowAllUnixSockets` for the herdr socket, and
    `WebFetch(domain:*)` so every host is reachable.
  - Permissions: `denyInsteadOfPrompting`.
  - Writes allowed: the repo's worktrees dir (every worktree of the repo,
    the lead's and its members' among them), the repo's main checkout, and
    loopherd's state dir.
  - Writes denied: loopherd's whole config dir (herd files, `config.toml`,
    and these settings files) and `~/.claude`. Each deny is both a sandbox
    `denyWrite` entry and an `Edit(//…/**)` rule.
  - Run outside the sandbox, each with a `Bash(…)` allow rule so it isn't
    denied for want of a prompt: `loopherd restart --self` always, and
    with `install = true`, `scripts/install`. `install = true` also allows
    writes to `~/.local/bin`.
- **`[lead] sandbox`.** `require` (the default) or `prefer`.
  - `lead` and `revive` probe the machine first. On macOS the sandbox is
    built in. On Linux and WSL2, `bwrap` and `socat` must be on PATH and
    `bwrap` must make a sandbox (this catches WSL1 and blocked user
    namespaces). Anything else can't run it.
  - `require` refuses with the reason: `lead` fails, `revive` reports
    `failed <lead>: sandbox: …`, and `restart` refuses a lead whose
    recorded args lack its settings.
  - `prefer` starts or keeps the lead without the sandbox, guarded by its
    tool hook alone, with a warning. `lead` also leaves the warning as a
    note in the lead's mailbox.
- **Doctor** runs the same probe and fails when the sandbox can't start. It
  warns for each herd on `prefer`.
- **Credentials stay readable.** `merge = true` and `hook` leads use the
  human's gh credentials. The deny on them is LH-281's, for `credentials`
  leads only.

## Why

- **Lead commands need more than the worktree.** A lead runs `feed` and
  `retire --close`, which create and remove its members' worktrees, and
  `feed` runs `after_merge` in the main checkout.
- **One deny covers the config dir.** Herd files, `config.toml` and the
  settings files all sit in it, so one deny covers them, and a lead can't
  loosen its own sandbox. It's also why `restart` writes nothing: its
  `--self` waiter runs on the lead's behalf.
- **The sandbox ends every process a command leaves behind.** A detached
  `setsid` child of a sandboxed Bash call didn't outlive the call (tried
  live), so `restart --self`'s waiter has to run outside the sandbox. That
  needs a `loopherd` the lead can't replace, which holds while `install`
  is off.
- **`install = true` is a trust grant, not a contained path.** The sandbox
  protects most of `~/.claude`, whatever `allowWrite` says, and the
  installer writes hooks, the skill and agents there, so it runs outside
  the sandbox. A lead with `install` on can edit `scripts/install` in its
  worktree before running it, and can replace `~/.local/bin/loopherd`,
  which hooks run outside the sandbox. Either way, `install = true` lets
  the lead write anything the human can. Turn it on only for a lead
  trusted with that.
- **Unix sockets can't be narrowed on Linux.** Claude Code ignores
  `allowUnixSockets` on Linux and WSL2, so a lead's Bash can reach any
  socket the human can, an ssh agent included.
- **The network stays open.** D83 left merges to credentials, and leads
  reach GitHub, their tracker, and whatever their members' builds need.
  On macOS, git over an SSH remote fails inside the sandbox, so a lead
  there needs an HTTPS remote.
- **Restart can't relaunch.** A lead started before its sandbox, or on
  `prefer`, stays unsandboxed until `revive` or a fresh `lead`. So under
  `require`, `restart` refuses instead of passing it as sandboxed. A
  switch changed since the lead started reaches its sandbox at the next
  `revive`.
