# D81

## Decision

`revive --startup` tells a live handoff from a restart by the pane shells,
since herdr 0.9.5 gives the hook no flag for it
([research](../research/herdr.md#handoff-or-restart-in-a-startup-hook-095-lh-263)).

- **Server.** The hook's parent pid: `loopherd.sh` `exec`s loopherd, and
  herdr spawns the hook from its server. Read from herdr's source, not yet
  seen in a real hook run.
- **Shells.** Every pane's `shell_pid` from `herdr pane process-info`. A
  shell whose parent isn't the server, or that started before it
  (`/proc/<pid>/stat` start ticks), means a handoff. A shell that is the
  server's child and started at or after it (ties included) means a
  restart. A pane with no shell yet (a pending agent resume), or a shell
  that has exited, says nothing. No deciding pane, or a failed herdr call
  (with a warning line), means a restart.
- **Effect.** After a handoff an alive lead whose watch isn't running is
  neither prompted to re-arm nor noted; its line reads `(not prompted:
  herdr handed off live, so its session kept running)`. A lead revive
  starts is prompted as after a restart. A restart behaves as before.
- **Cross-check.** When the server's argv is readable and its
  `--handoff-import` (an internal herdr flag) disagrees with the shells,
  revive prints a warning line; the shells still decide.
- **macOS.** No `/proc`, so nothing decides and it stays a restart, as
  before.

LH-246 settled it.

## Why

A lead between watches (mid-wake, handed off, or drained) is still running
after a live handoff, so a re-arm prompt only interrupts it. The parent pid
needs no clocks; the start time catches a shell the new server adopted.
Defaulting to a restart keeps the old behaviour wherever the signal is
missing, costing a spurious prompt rather than a lead left without a watch.
`restore_error` isn't read because a handoff can set it too.
