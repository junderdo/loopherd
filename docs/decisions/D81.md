# D81

## Decision

`revive --startup` tells a live handoff from a restart by the pane shells,
since herdr 0.9.5 gives the hook no flag for it
([research](../research/herdr.md#handoff-or-restart-in-a-startup-hook-095-lh-263)).

- **Server.** The hook's parent pid: `loopherd.sh` `exec`s loopherd, and
  herdr spawns the hook from its server. Read from herdr's source, not yet
  seen in a real hook run. Unless that pid's executable is `herdr` (a
  manual `revive --startup`, or a wrapper that doesn't `exec`), it is a
  restart, with a warning.
- **Shells.** A shell outlived the server when its parent isn't the
  server, or it started before it. A shell that is the server's child and
  started at or after it (ties included) didn't. A pane with no shell yet
  (a pending agent resume), or a shell that has exited, says nothing.
  Without the server's start time, the parent alone decides.
- **Per lead.** An alive lead's own pane shell decides when it says
  anything; otherwise any outliving shell in the server's panes means a
  handoff. So a lead pending resume at the handoff, whose shell and Claude
  are the new server's, is still prompted. A failed herdr call means a
  restart, with a warning.
- **Effect.** After a handoff an alive lead whose watch isn't running is
  neither prompted to re-arm nor noted; its line reads `(not prompted:
  herdr handed off live, so its session kept running)`. A lead revive
  starts is prompted as after a restart. A restart behaves as before.
- **Cross-check.** When the server's argv is readable (Linux) and its
  `--handoff-import` (an internal herdr flag) disagrees with the shells,
  revive warns; the shells still decide.
- **Warnings.** Each is printed and noted, as `herdr's startup revive:
  warning: …`, in every lead's mailbox the startup revive notes, so the
  shepherd's watch shows it.
- **Platforms.** Linux reads `/proc/<pid>/stat` (start in clock ticks
  since boot) and `/proc/<pid>/exe`. macOS reads `proc_pidinfo`
  `PROC_PIDTBSDINFO` (parent, and start in microseconds: the kernel's
  `p_start`, which sysctl `KERN_PROC_PID` also reports, and which libc
  exposes without a hand-written `kinfo_proc`) and `proc_pidpath`. Start
  times are only compared on one machine.

LH-246 settled it.

## Why

A lead between watches (mid-wake, handed off, or drained) is still running
after a live handoff, so a re-arm prompt only interrupts it. The parent pid
needs no clocks; the start time catches a shell the new server adopted.
Every doubt resolves to a restart, which costs a spurious prompt rather
than a lead left without a watch, and the warning says why it happened.
Deciding per lead keeps a lead herdr resumed on the new server from being
skipped. `restore_error` isn't read because a handoff can set it too.
