# D59

## Decision

`loopherd release` deletes origin's branch with the repo's pre-push hooks
running: the push carries no `--no-verify`, and release offers no flag to
add one. When a hook refuses, release leaves the branch on origin, finishes
the rest (worktree, local branch) but leaves the entry unreleased, prints git's output with the
hook's (stderr and stdout, the last 20 lines of each), and exits non-zero. Once the hook passes,
rerunning release deletes the branch and marks the entry released. The hook runs inside the push's
`LOOPHERD_GIT_TIMEOUT` (120 s by default), so a slower hook needs it raised.

LH-219 settled it; LH-235 moved the release mark after the delete.

## Why

A pre-push hook is the repo owner's policy, and a delete is a push like any
other. Skipping it would let loopherd do what the human's own `git push`
couldn't. The cost is a release that can stop short. Had the entry been
released already, a feed could start a new member from the leftover
branch, dropped commits included, for as long as the hook kept refusing,
which lasts until the human acts. So the entry stays unreleased, and feed
skips the name, until a rerun deletes the branch.
