# D59

## Decision

`loopherd release` deletes origin's branch with the repo's pre-push hooks
running: the push carries no `--no-verify`, and release offers no flag to
add one. When a hook refuses, release leaves the branch on origin, finishes
the rest (worktree, local branch, ledger), prints git's output with the
hook's (stderr and stdout, the last 20 lines of each), and exits non-zero. Once the hook passes,
rerunning release deletes the branch. The hook runs inside the push's
`LOOPHERD_GIT_TIMEOUT` (120 s by default), so a slower hook needs it raised.

LH-219 settled it.

## Why

A pre-push hook is the repo owner's policy, and a delete is a push like any
other. Skipping it would let loopherd do what the human's own `git push`
couldn't. The cost is a release that can stop short. The entry is already
released then, so until a rerun deletes the branch, a feed may start a new
member from it, dropped commits included. D51 accepted that window for a
brief network failure; a refusing hook holds it open until the human acts,
so release's error names it.
