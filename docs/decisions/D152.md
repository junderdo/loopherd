# D152

## Decision

With a lead's `merge` switch on, the shepherd runs its gates (LH-532, the
human's call on 2026-11-24). When a review passes, the lead reports a `note`
starting `Gate request: #<n> (LH-<m>) at <full sha>` and keeps working; the
shepherd runs fmt, clippy and `cargo test` on that head, unsandboxed but with
temp config and state dirs and no herdr socket, and answers `Gate PASS` or
`Gate FAIL` with `loopherd tell`. The lead merges a PASS head and sends a
FAIL back to the member as a blocking finding. With `merge` off, the human
still gates and merges.

## Why

A lead's sandbox can't run the full suite (read-only `/tmp`, no sockets), so
every passed review waited on the human to run it and reply. The shepherd
runs outside the sandbox and already verifies work, so it can gate without
the human, who keeps the merge whenever `merge` is off. A note, not a
question, keeps gate requests from notifying the human. `loopherd gate`
(LH-419) lets a lead's broker run the gate itself; once herds use it, this
routing can go.
