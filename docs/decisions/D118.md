# D118

Amends D19.

## Decision

`loopherd install-hook` installs the skill the way the `skills` CLI installs
one: the file in `$HOME/.agents/skills/loopherd/SKILL.md`, and
`<claude dir>/skills/loopherd` (`$CLAUDE_CONFIG_DIR`, else `~/.claude`) a
relative symlink to it (`../../.agents/skills/loopherd` by default).

- A real `<claude dir>/skills/loopherd` holding only a SKILL.md whose
  frontmatter opens `name: loopherd` is the pre-D118 copy, and is replaced by
  the link. Anything else there (other files, a non-loopherd SKILL.md, a
  symlink resolving elsewhere, a plain file) is the human's: install-hook
  leaves it, prints why and to move it aside and rerun, and still installs
  the hooks.
- Installs take turns under an `flock` on `<claude dir>/skills`. A missing
  link is made in place, which fails with EEXIST rather than replace
  anything that appeared there meanwhile. An old copy is replaced by a link
  made under a temp name and renamed into place, the copy first moved aside
  and put back if the rename fails. Either way, a failure that still leaves
  our link there counts as success.
- `--remove` deletes the link only when it resolves to the skill dir, then
  the SKILL.md and its directory if that leaves it empty. A link that
  dangles because the human deleted the skill dir still counts as ours when
  its target is the relative path install-hook writes, so `--remove` deletes
  it and a plain `install-hook` relinks it. Any other dangling link is the
  human's to remove by hand.
- A symlink at `~/.agents/skills/loopherd` is the human's: install-hook and
  `--remove` refuse to write or delete through it, and fail before touching
  the settings; doctor warns about it.
- Without `HOME`, install-hook leaves the skill out and still installs the
  hooks, and doctor skips the skill check.
- `--skills-dir <dir>` writes `<dir>/loopherd/SKILL.md` directly, as before.
  `--settings <file>` puts both `.agents/skills` and `skills` in the settings
  file's own directory (link `../.agents/skills/loopherd`), so neither tests
  nor manual runs touch `$HOME`. A settings file in the claude dir itself
  (`--settings ~/.claude/settings.json`) takes the `$HOME/.agents/skills`
  layout instead, so the two runs agree.
- `~/.agents/.skill-lock.json` is never read or written; loopherd isn't
  registered with the `skills` CLI.
- `loopherd doctor` warns when the link is missing, isn't a symlink, points
  elsewhere, or the skill file behind it is gone, naming `loopherd install-hook`.

## Why

Every skill the human installed with the `skills` CLI sits in
`~/.agents/skills/<name>/` behind a relative link from `~/.claude/skills`,
where other agents that read `~/.agents/skills` find it too; loopherd's was
the odd real directory out (LH-336). The card put the `--settings` layout
beside the settings file's parent, but for the usual `--settings
<temp dir>/settings.json` or `--settings $(mktemp)` that is `/tmp/.agents` or
`/.agents`, shared or unwritable, so it stays inside the settings file's
directory instead.
